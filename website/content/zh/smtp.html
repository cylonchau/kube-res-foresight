邮件通道是什么，谁在用

邮件通道让平台通过一台 SMTP 服务器给指定邮箱发信。目前用它的是 AI 定时任务：任务按计划让模型回答，再把回答发给收件人。通道本身只管“把一封信交给 SMTP 服务器”，不管内容；没有配置好时，任务运行会失败并在任务中心写明原因，不会静默丢信。

配置全部在“系统管理 → 系统参数”的通知分类里，没有配置文件。每一项单独保存，刚保存的参数最多 10 秒后生效。配好后用同一页的“发送测试邮件”按钮给自己发一封，是最快的验证办法。

参数

参数默认值含义
notify.email.host空SMTP 服务器主机名或 IP。为空表示邮件通道没有配置，发送会直接失败。
notify.email.port587端口，1 到 65535。常见搭配：587 + starttls，465 + tls，25 + none。
notify.email.securitystarttls连接加密方式：starttls（先明文连接再升级为加密）、tls（整条连接一开始就是 TLS，也叫隐式 TLS / SMTPS）、none（不加密）。
notify.email.username空登录 SMTP 服务器的账号。服务器不需要登录时留空。
notify.email.password空账号的密码或应用专用密码。加密保存，保存后只显示掩码；提交掩码表示保持原值。
notify.email.from空发件地址，必填。可以写 reports@example.com，也可以写带显示名的 "kube-res-foresight <reports@example.com>"。邮件服务通常要求它与登录账号一致或是该账号有权代发的地址。
notify.email.skip_verifyfalse是否跳过服务器证书校验。服务器用自签名证书时才临时打开；打开后连接可能被冒充，能提供受信任证书时不要开。
notify.email.timeout_seconds30一封邮件从连接、登录到交付给服务器的总时限，5 到 300 秒。

“启用”没有单独的开关：host、port、from 都有效，通道就可用。

加密与密码：什么时候会发送登录密码

平台使用标准的 SMTP PLAIN 登录。出于安全，账号密码只会在加密连接上发送，或者发给本机上的服务器；在一条不加密的外部连接上，登录会被拒绝，而不是把密码明文发出去。

security典型端口过程能否带账号密码
starttls587先用明文连上并问候，服务器必须声明支持 STARTTLS，然后升级为 TLS，再登录和发信。服务器不支持时报错而不是退回明文。可以（升级之后）
tls465一开始就建立 TLS，之后登录和发信。可以
none25全程不加密。只有服务器在本机时可以；用于内网无认证的中继。

自签名证书的内部服务器

先按服务器实际的端口和加密方式填，再把 notify.email.skip_verify 设为 true。这只是权宜之计：证书不校验，连接可能被冒充；长期使用应给服务器换成受信任的证书。

发出的邮件长什么样

邮件内容用 UTF-8，经 base64 编码，中文主题也能正常显示。任务回答是 HTML 时，邮件同时带纯文本和 HTML 两个版本（multipart/alternative）：支持 HTML 的邮箱客户端显示带标题、表格和颜色的版本，其他客户端显示纯文本。平台会去掉 HTML 里的脚本、框架和对象，邮件客户端本来也不会显示它们。内容里的换行不会被用来构造邮件头。

一封邮件发给一个收件人；一个任务有多个收件人时分别发送，其中某个失败不会让已经发成功的重发。

先发一封测试邮件

“系统管理 → 系统参数”里，通知分类有“发送测试邮件”：填一个收件邮箱，平台用当前保存的参数发一封测试信。成功会提示已发送；失败时直接显示邮件服务器的原话，这是排查最有用的信息。刚改的参数最多 10 秒后生效，改完请稍等再测。

排查

提示（节选）原因与检查
the e-mail channel is not set up: the SMTP host (notify.email.host) is empty没有填主机。
the SMTP port (notify.email.port) is not valid端口不在 1 到 65535。
the sender address (notify.email.from) is not set / is not valid发件地址为空或格式不对；带显示名时要写成 名称 <地址>。
the security (notify.email.security) is starttls, tls or nonesecurity 只能是这三个值之一。
could not reach the SMTP server host:port连不上：主机名、端口、防火墙或出站网络策略。容器里要确认平台所在的 Pod 能访问该地址。
the SMTP server did not greet连上了但服务器没有按 SMTP 问候，常见于端口与加密方式不匹配，例如在 465 上用了 starttls，应改成 tls。
the SMTP server does not offer STARTTLS服务器不支持升级加密：换成它支持的方式（tls），或确认是不加密的内网中继再用 none。
STARTTLS failed / 证书相关错误证书不被信任或域名不匹配。检查服务器证书；自签名证书可临时开 skip_verify。
the SMTP server refused the sign-in账号或密码不对，或服务器要求应用专用密码、没有允许该账号用 SMTP 登录。
the SMTP server refused the sender发件地址不被允许：通常要与登录账号一致，或该账号有权代发。
the SMTP server refused the recipient …收件地址被拒绝：地址错误，或服务器不允许向外部域发信（中继限制）。

任务运行失败时，错误也会出现在任务中心的运行记录里，已经发送成功的收件人不会因为重试再收到一次。
