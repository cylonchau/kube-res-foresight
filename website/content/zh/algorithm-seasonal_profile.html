用途与适用负载

按一天中的时段和周几分桶，对每个桶取衰减百分位。适合“工作日上午忙、周末安静”等有时钟规律的负载。

历史数据与运行条件

运行最低 4 点；周几画像需要足够周历史与桶样本。不够时依次退到每日同一时刻、整段历史百分位。

输入应是等间隔、无缺口且数值有限的序列。输出保留输入指标单位，例如 CPU 核、内存字节或每秒请求数；采样步长决定步数对应的真实时间。最低样本数仅表示可运行，不代表预测可靠。

此方法不使用协变量；分别预测各目标指标。

参数说明

窄屏可左右滑动参数表，查看完整说明。

参数 / 类型默认值 / 范围 / 单位含义与使用
percentile
float		90
≥ 1; ≤ 100		取第几百分位，如 90、95；越大越保守。
bucket_minutes
int		60
≥ 1; ≤ 720; minutes		时间桶的长度（分钟），必须能整除一天（1440）：60 = 每小时一个桶，15 = 每 15 分钟一个桶。
by_weekday
bool		true
无额外范围限制		是否区分周几：true = 周一九点和周六九点是两个桶（至少需要两周历史才有各自的数据，不够时退到每天同一时刻）；false = 只看一天中的时刻。
half_life_days
float		14
≥ 0; ≤ 365; days		半衰期：这么多天之前的样本只算一半权重；0 表示不衰减。
min_samples_per_bucket
int		6
≥ 1; ≤ 100000		一个桶至少有多少个样本才被信任；不够就退到上一级（每天同一时刻，再退到整段历史）。
utc_offset_minutes
int		480
≥ -720; ≤ 840; minutes		时区偏移（相对 UTC，分钟），决定「几点」「周几」按哪个时区的钟面分桶。默认 480（UTC+8，平台的时区）：这样「九点」是北京时间九点，周一从北京时间零点开始；部署在别的时区就改成那里的偏移。
safety_margin
float		0
≥ 0; ≤ 5		安全边际：结果再乘 (1+边际)。

配置示例

在“算法管理”编辑参数。以下仅为参数对象，不是 config.yaml 全文；周期示例按 5 分钟采样，需按实际步长调整。未列出的可选参数使用上表默认值。

{
  "percentile": 90,
  "bucket_minutes": 60,
  "by_weekday": true,
  "half_life_days": 14,
  "utc_offset_minutes": 480
}

调参与取舍

bucket_minutes 必须整除 1440。更小的桶需要更多历史。utc_offset_minutes=480 按 UTC+8 分桶，是固定偏移，不会自动处理夏令时。

通用参数：变化重置与分位校准

参数 / 类型默认值 / 范围 / 单位含义与使用
reset_on_change
bool		false
无额外范围限制		水平突变后重置：检测历史里最后一次水平突变（发布、扩缩容、流量切换），只用突变之后的历史预测。关闭时用全部历史（现状）。突变之后至少要有 6 步才会被确认；突变后的历史不够算法所需时，取算法所需的最新一段。
change_threshold
float		8
≥ 3; ≤ 50		突变阈值：突变幅度（扣除前一段趋势后）超过噪声的多少倍才算，越大越不容易误报，噪声由相邻步变化的稳健标准差估计。仅 reset_on_change=true 时使用。
change_min_shift
float		0.2
≥ 0; ≤ 5		最小突变幅度：突变至少是水平的这个比例（0.2 = 20%），很干净的序列上的微小跳变不算。仅 reset_on_change=true 时使用。
quantile_level
float		0
≥ 0; ≤ 0.99		推荐分位数：0 = 点预测（现状）；0.9 等 = 预测「实际值有约 90% 的把握不超过」的线（保形预测：用本算法在这个负载最近几个窗口里的真实误差校准，需要更多历史和时间）。必须大于 0.5。
calibration_windows
int		8
≥ 3; ≤ 50		校准窗口数：用最近多少个历史窗口测本算法的误差；越多越稳，也越慢（每个窗口多跑一次预测）。仅推荐分位数大于 0 时使用。

quantile_level 是 0～1 的分位点，percentile 是 1～100 的百分数，二者不是同一参数。分位校准会额外运行历史预测；增加校准窗口前检查历史与运行预算，覆盖率是评估目标而非保证。

在模块中使用

  1. 保存参数，检查历史窗口、采样步长和预测范围。
  2. 打开模块的“启用预测”；固定算法只运行指定方法，动态算法使用平台已启用的方法。
  3. 先运行滚动回测，通过版本晋升后才会采用；修改影响模型版本的参数后重新回测。
  4. 在仅观察或仅推荐下检查误差、峰值低估、耗时与采用原因，再分别授权准入和副本执行。

历史不足、参数不合法、运行超时或输出无效时，检查算法运行原因；没有合格预测时按模块的固定周期、兜底与保护规则处理。
