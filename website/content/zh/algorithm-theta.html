用途与适用负载

将平滑水平与线性趋势斜率的一半结合，支持先去季节。适合作为带噪声趋势序列的候选，预测下限为 0。

历史数据与运行条件

无季节项至少 4 个点；有季节项至少两个完整周期。

输入应是等间隔、无缺口且数值有限的序列。输出保留输入指标单位，例如 CPU 核、内存字节或每秒请求数；采样步长决定步数对应的真实时间。最低样本数仅表示可运行，不代表预测可靠。

此方法不使用协变量；分别预测各目标指标。

原理与公式

Theta 方法是 M3 预测竞赛的获胜方法。简化形式（Hyndman 与 Billah）等价于：先对序列做简单指数平滑得到“水平”，再加一个“漂移”，漂移取线性趋势斜率的一半。水平跟着近期走，趋势只信一半，所以在短而有噪声的序列上很难被击败。

x = 去季节后的序列（无季节时就是原序列）
ℓ  = 对 x 做简单指数平滑得到的最后一个水平（系数 α）
b  = x 对时间做最小二乘直线的斜率（每步）
n  = 序列长度

ŷ(T+h) = ℓ + (b/2) · ( (h−1) + 1/α − (1−α)ⁿ / α )        h = 1 … H
最后把季节项放回去，并把小于 0 的预测截为 0

括号里第一项 (h−1) 表示每向前一步漂移再多走一步；1/α − (1−α)ⁿ/α 是平滑水平与趋势线之间的固定偏移。

参数怎样进入公式：

  • alpha：水平的平滑系数。填 0 表示自动选择：在 0.05、0.10 … 1.00 上试，取历史上一步预测误差平方和最小的 α。
  • season_length_steps（m）：季节长度（步数）。0 或 1 表示不带季节；带季节时至少要 2m 个点。带季节时先用经典分解（居中移动平均）算每个位置的季节指数：历史全为正数时用乘性（序列除以指数），否则用加性（序列减去指数），预测后再放回。

为什么这样做：只看水平会落后于上升趋势，完整外推趋势又容易冲过头。折中取一半斜率，既能跟上缓慢的变化，又不会被几个点带偏。不需要训练，也不需要调很多参数。

计算示例：数据、参数与代入过程

不带季节，手工指定 α（这样不做自动选择）。每 5 分钟一个点。

{
  "alpha": 0.5
}
y = [10, 12, 11, 13, 14, 16]        n = 6

第 1 步，简单指数平滑得到水平 ℓ（ℓ(1) = 10，之后 ℓ ← 0.5·y + 0.5·ℓ）：10 → 11 → 11 → 12 → 13 → 14.5。

第 2 步，最小二乘斜率 b：对 (0,10)、(1,12)、(2,11)、(3,13)、(4,14)、(5,16) 做直线，斜率 1.0857 每步。

第 3 步，代入公式。(1−α)ⁿ = 0.5⁶ = 0.015625，所以 1/α − (1−α)ⁿ/α = 2 − 0.03125 = 1.96875，b/2 = 0.54285：

ŷ(T+1) = 14.5 + 0.54285 × ( 0 + 1.96875) = 15.5687
ŷ(T+2) = 14.5 + 0.54285 × ( 1 + 1.96875) = 16.1116
ŷ(T+3) = 14.5 + 0.54285 × ( 2 + 1.96875) = 16.6545

结果 [15.5687, 16.1116, 16.6545]。对比：如果完整外推趋势（斜率 1.0857 而不是一半），每向前一步会多 1.09；Theta 每步只多 0.54，这就是“趋势只信一半”。

这些数字由 pkg/forecast/docs_examples_test.go 用真实代码算出并持续校验。

调参与取舍

alpha=0 自动选择平滑强度；先从无季节版本比较，确认周期明确且历史充足后再设置 season_length_steps。

通用参数：变化重置与分位校准

参数 / 类型默认值 / 范围 / 单位含义与使用
reset_on_change
bool		false
无额外范围限制		水平突变后重置：检测历史里最后一次水平突变（发布、扩缩容、流量切换），只用突变之后的历史预测。关闭时用全部历史（现状）。突变之后至少要有 6 步才会被确认；突变后的历史不够算法所需时，取算法所需的最新一段。
change_threshold
float		8
≥ 3; ≤ 50		突变阈值：突变幅度（扣除前一段趋势后）超过噪声的多少倍才算，越大越不容易误报，噪声由相邻步变化的稳健标准差估计。仅 reset_on_change=true 时使用。
change_min_shift
float		0.2
≥ 0; ≤ 5		最小突变幅度：突变至少是水平的这个比例（0.2 = 20%），很干净的序列上的微小跳变不算。仅 reset_on_change=true 时使用。
quantile_level
float		0
≥ 0; ≤ 0.99		推荐分位数：0 = 点预测（现状）；0.9 等 = 预测「实际值有约 90% 的把握不超过」的线（保形预测：用本算法在这个负载最近几个窗口里的真实误差校准，需要更多历史和时间）。必须大于 0.5。
calibration_windows
int		8
≥ 3; ≤ 50		校准窗口数：用最近多少个历史窗口测本算法的误差；越多越稳，也越慢（每个窗口多跑一次预测）。仅推荐分位数大于 0 时使用。

quantile_level 是 0～1 的分位点，percentile 是 1～100 的百分数，二者不是同一参数。分位校准会额外运行历史预测；增加校准窗口前检查历史与运行预算，覆盖率是评估目标而非保证。

在模块中使用

  1. 保存参数，检查历史窗口、采样步长和预测范围。
  2. 打开模块的“启用预测”；固定算法只运行指定方法，动态算法使用平台已启用的方法。
  3. 先运行滚动回测，通过版本晋升后才会采用；修改影响模型版本的参数后重新回测。
  4. 在仅观察或仅推荐下检查误差、峰值低估、耗时与采用原因，再分别授权准入和副本执行。

历史不足、参数不合法、运行超时或输出无效时，检查算法运行原因；没有合格预测时按模块的固定周期、兜底与保护规则处理。
