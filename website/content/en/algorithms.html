Central model settings

Manage activation, parameters, weights, budgets, and adoption thresholds centrally. Modules with prediction enabled in dynamic mode use the platform's enabled methods without separate instances or manual binding.

Inspect model runs for insufficient history, missing parameters, and timeout. A rank or model name alone does not determine suitability.

Derived and formula models

Create derived models from built-in methods or define parameterized formulas. Check outputs and input requirements before saving. Parameter or implementation changes affect version identity and adoption eligibility.

Choosing and adopting models

Align forecast horizon and historical window, then compare resource error, peak underestimation, stability, and runtime. Available model forecasts can participate in look-ahead consensus; rank is not the sole basis for execution.

Choose how a module predicts

Prediction is disabled for new modules. History collection continues, recommendations use configured fallback defaults, and no algorithms run. Enable prediction when ready to use models, then choose a mode.

Prediction modeHow advice is producedWhen to use it
No predictionUse fixed defaults without running algorithms; this is intentional configuration, not degradation.Collect history first or operate with known defaults.
Fixed algorithmRun one selected algorithm without score-based switching. Non-baseline models still require backtest promotion.Keep a selected forecasting method explicit.
Dynamic algorithmsRun centrally enabled methods and use scores, recent errors, and eligibility. Dynamic replica decisions combine eligible candidates' votes.Compare methods continuously as workload patterns change.

A fixed algorithm continues running for its module even when disabled centrally. It bypasses the module's minimum overall score filter, while version promotion and resource safeguards still apply. Prediction mode is independent of Observe, Recommend, Admission, and Auto: enabling a model does not authorize cluster writes.

Keep seasonal models responsive

For applicable seasonal and long-memory methods, recent predictions are compared with actuals. Significant rises add a short-term correction that fades over time. Downward correction is disabled by default to limit the risk of reacting to a brief dip. Combination forecasting also penalizes underestimation more heavily, trims much weaker members, and includes recent errors in its weights.

Changes to models or correction parameters require renewed backtest promotion. Seasonal patterns and short-term corrections still operate within resource bounds and execution safeguards.
