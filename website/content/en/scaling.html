Let the Operator adjust replicas

Configure the target workload, replica bounds, step limits, and cooldowns. Auto requires authorization at both module and global levels before the Operator applies valid advice.

Manage settings directly through platform modules or use declarative PredictiveScaler configuration. Both require a clear target and replica owner.

One replica owner per target

Do not let the Operator, HPA, KEDA, or duplicate scalers write the same workload. Stop the previous controller and release ownership before reviewing the new controller in Observe.

Apply resource advice to new Pods

Admission reads the latest valid recommendation and adjusts CPU / memory requests and configured limits on new Pods. Unavailable advice should preserve original resources and allow deployment.

New recommendations do not immediately change running Pods. Apply settings through creation or rolling updates. Assess and authorize memory-limit reductions separately.

Review actual outcomes

Inspect scaling and admission details for advice, applied results, and pause or failure reasons. Check current and Ready replicas, workload demand, and resource use to distinguish a submitted change from ready capacity.
