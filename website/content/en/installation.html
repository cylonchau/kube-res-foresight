Choose the components

The platform provides the console, data management, forecasting, and advice. The job engine runs recurring work. Add the Operator for replica changes and admission policies for resource advice on new Pods.

ComponentPurpose
PlatformConsole, API, metrics, forecasts, and recommendations.
Job engineRecurring collection, forecasts, backtests, and evaluations; can run with the platform.
OperatorAdjust workload replicas within authorization and bounds.
Resource admissionApply valid resource advice to new Pod requests / limits.

Build the platform

Use the Go, Node.js, and pnpm toolchains declared by the repository. The web/ frontend is a separate repository; prepare its sources before building.

cd web
pnpm install --frozen-lockfile
cd ..
make package-web
mkdir -p target/bin
go build -o target/bin/kube-resource-fcst ./cmd

Configure and start

Set the database, listener, logging, and stable JWT key in config.yaml. Choose SQLite, MySQL, or PostgreSQL. Environment variables use KUBE_RESOURCE_FCST_; credentials use the encryption key KUBE_RESOURCE_FCST_SECRET_KEY.

# First installation: explicit migration
target/bin/kube-resource-fcst server --config config.yaml --migration

# Start the platform and job engine
target/bin/kube-resource-fcst all --config config.yaml

The example port is 20001. Open http://localhost:20001 after startup. The server and job commands can also run separately.

Existing installations and execution

Keep the existing database connection, path, and key values. Back up before upgrading and review the cleanup performed by --upgrade. Normal startup does not remove retired tables.

Prepare cluster permissions, credentials, certificates, and policies for execution. Begin in Observe and review resource references and replica ownership before authorizing changes.
