How a login is told apart

The sign-in page has no source option. The platform decides from the user name and the local database:

CaseResult
The name exists locally and is a local accountOnly the local password is checked; the directory is not contacted. admin keeps working when the directory is down.
The name exists locally and is an LDAP accountThe password is checked against the directory only.
The name is unknown and LDAP is enabledThe directory authenticates. On success the roles come from the role mappings and the LDAP user is created.
The name is unknown and LDAP is disabledThe login fails.

A directory user with the same name as a local account never takes it over. An LDAP user's local password is random and unusable, and the password cannot be changed in the user center; change it in the directory. The user list and the user center show the account source.

Parameters

Set them one by one under System → System parameters, in the LDAP category. Each is saved on its own.

ParameterMeaning
ldap.urlDirectory address, such as ldaps://ldap.example.com:636. ldap:// requires StartTLS.
ldap.start_tls / ldap.skip_verifyStartTLS; whether to skip certificate verification. Do not skip it when you can provide the CA.
ldap.ca_certCA (PEM) for a self-signed certificate. Shown masked after saving.
ldap.bind_dn / ldap.bind_passwordService account used to look users up. The password is stored encrypted; set the bind DN first.
ldap.user_base_dnWhere the user search starts, such as dc=example,dc=com.
ldap.user_filterFilter that finds the user. It must contain exactly one %s (the login name), for example (cn=%s) or (&(objectClass=person)(uid=%s)).
ldap.display_name_attr / email_attr / phone_attrAttributes for display name, email and phone, refreshed at each login.
ldap.member_of_attrAttribute of the user entry that lists the DNs of its groups, usually memberOf. When set, the groups are read from it.
ldap.group_base_dn / ldap.group_filterWithout memberOf, look the user up in the group entries: in the filter %s is the user DN and %u the login name, such as (member=%s). Both are set or both are empty: setting one while the other is empty fills in a usual value, and clearing one clears both.
ldap.group_name_attrAttribute of a group entry used as its name, cn by default.
ldap.group_role_mappingsGroup-to-role mappings, below.
ldap.default_role_codeRole of users in no mapped group. Empty means those users cannot sign in.
ldap.timeout_secondsConnection and query timeout, 1 to 120 seconds.
ldap.enabledWhether directory login is on.

Enabling validates the whole configuration and connects to the directory once. If that fails, LDAP is not enabled and the reason is shown, so set ldap.enabled last.

Two ways to get the groups

Use either, or both: the results are merged.

  • Read memberOf of the user: set ldap.member_of_attr; no group base DN or filter is needed. Each value (a group DN) matches either as the full DN or as the value of its first RDN (cn=ops,ou=groups,… matches ops).
  • Search the group entries: set ldap.group_base_dn and ldap.group_filter, and take the name from ldap.group_name_attr. Usual filters: (member=%s) for OpenLDAP groupOfNames, (memberUid=%u) for posixGroup, and (member:1.2.840.113556.1.4.1941:=%s) for AD when nested groups count.

Role mapping

ldap.group_role_mappings takes one group=role code per line:

ops=ADMIN
dev=VIEWER
ou=sre,ou=platform,dc=example,dc=com=ADMIN
  • The left side is a group name (cn) or a full DN, case-insensitive; spaces inside a full DN must match what the directory returns.
  • The right side is the role code, listed under Authorization → Roles. The role must exist and be enabled.
  • The line is split at the last =, so full DNs work as they are. A group may appear on several lines to grant several roles; a user in several groups gets the union.
  • Lines starting with # are comments and blank lines are ignored. A malformed or repeated line is rejected on save.

A user in no mapped group gets ldap.default_role_code; with neither, the login is refused. An existing LDAP user who loses every role is disabled and their sessions end.

The org_role of Grafana (Admin, Editor, Viewer) has no fixed counterpart here: use your own role codes. The built-in administrator role is ADMIN and has every permission, so check before granting it to a whole group.

Synchronization and disabling

Users who were deleted or disabled in the directory, or who no longer belong to a mapped group, are disabled by the synchronization and lose their sessions; users the directory enabled again are restored, except those an administrator disabled. When the directory cannot be reached no account is changed, so an outage does not lock everyone out.
