Purpose and workload fit

Models level, trend, and seasonality with additive or multiplicative seasons and optional damped trend. Suitable for cyclic demand with changing levels.

History and runtime requirements

At least two complete cycles with seasonality, or four observations without it.

Inputs must be regularly sampled, gap-free, and finite. Outputs retain the metric unit, such as CPU cores, memory bytes, or requests per second. The sample interval determines the duration of a step. Minimum history permits execution; it does not establish forecast quality.

This method does not use covariates; target metrics are forecast separately.

How it works and the formula

Holt-Winters belongs to the exponential smoothing (ETS) family: it splits a series into a "level" ℓ, an optional "trend" b and an optional "season" s. With every new observation the three parts are updated with smoothing coefficients, and a forecast puts them back together.

let base(t) = ℓ(t−1) + φ·b(t−1)                      (φ = damping factor; φ = 1 without damping)

no season:             ŷ(t) = base(t)
additive season:       ŷ(t) = base(t) + s(t mod m)
multiplicative season: ŷ(t) = base(t) × s(t mod m)

updates (y is the observation):
  level   ℓ(t) = α·(y(t) − s) + (1−α)·base(t)              y(t)/s instead of y(t)−s when multiplicative
  trend   b(t) = β·(ℓ(t) − ℓ(t−1)) + (1−β)·φ·b(t−1)        (when trend is on)
  season  s(t mod m) = γ·(y(t) − ℓ(t)) + (1−γ)·s(t mod m)  γ·y(t)/ℓ(t) when multiplicative

h steps ahead:  ŷ(T+h) = ℓ(T) + (φ + φ² + … + φʰ)·b(T)    plus (or times) the season term of that position

How the parameters enter the formula:

  • alpha, beta, gamma: the smoothing coefficients of level, trend and season, 0 to 1, the larger the faster they follow new data. 0 means choose automatically: a small grid is tried (alpha ∈ {0.1, 0.3, 0.5, 0.7, 0.9}, beta ∈ {0.01, 0.1, 0.3}, gamma ∈ {0.1, 0.3, 0.5}) and the combination with the smallest in-sample one-step squared error wins.
  • trend: whether there is a trend term b. damped and damping_phi: whether the trend is damped, φ defaults to 0.98; a damped trend is multiplied by φ for each step ahead, so the forecast does not shoot up without end.
  • season_length_steps (m) and seasonal_mode: the season length in steps and additive / multiplicative. m = 0 means no season; with a season at least 2m points are needed. Multiplicative seasonality needs a history strictly above 0: a zero is refused, not quietly changed.
  • non_negative: a forecast below 0 is cut to 0.

Why it is done this way: level, trend and season are updated with coefficients of their own, so the model follows a "slow rise" and a "daily swing" at once, in a single pass with no training. Multiplicative seasonality suits a resource whose daily swing grows with the load; additive suits one whose swing stays about the same.

Initialisation: with a season the level is the mean of the first cycle, the trend is the difference of the means of the first two cycles divided by m, and the season terms are the differences (or ratios) of the first cycle's points to its mean; without a season the level is the first value and the trend is the least-squares slope of the first 10 points (all of them when fewer), so one noisy point does not set the starting trend.

Worked example: data, parameters and substitution

To see the updates clearly we use the simplest form: no season, a trend only, and the coefficients set by hand (so there is no grid search). Parameters:

{
  "trend": true,
  "alpha": 0.5,
  "beta": 0.3
}
y = [10, 11, 12.5, 13, 14.5, 15]        one point every 5 minutes

Initialisation: level ℓ = y(1) = 10; trend b = the least-squares slope of the 6 points = 1.0286. No damping, φ = 1.

Point by point: first predict the point from the old state with base = ℓ + b, then update with the actual value:

Row 1 as an example: base = 10 + 1.0286 = 11.0286; ℓ = 0.5×10 + 0.5×11.0286 = 10.5143; b = 0.3×(10.5143 − 10) + 0.7×1.0286 = 0.8743.

Forecast: the final state is ℓ = 15.0859, b = 0.9260; no damping, so

ŷ(T+1) = 15.0859 + 1×0.9260 = 16.0119
ŷ(T+2) = 15.0859 + 2×0.9260 = 16.9379
ŷ(T+3) = 15.0859 + 3×0.9260 = 17.8639

The result [16.0119, 16.9379, 17.8639] follows the latest trend, about 0.93 more per step. With damped on (φ=0.98) the increment becomes 0.926×(0.98 + 0.98² + 0.98³): growth slows step by step and a long forecast range does not shoot up.

These numbers are computed by the real code in pkg/forecast/docs_examples_test.go and checked on every test run.

Tuning and tradeoffs

Start with automatic smoothing coefficients (0). Enable damped to limit distant trend growth. Multiplicative mode needs a season of at least two steps and strictly positive history; use additive for zeros.

Sources and references

  • Holt, C.C. "Forecasting seasonals and trends by exponentially weighted moving averages", International Journal of Forecasting 20(1), 2004, 5–10 (a reprint of the 1957 ONR research memorandum): the trend term.
  • Winters, P.R. "Forecasting sales by exponentially weighted moving averages", Management Science 6(3), 1960, 324–342: the seasonal term (additive and multiplicative).
  • Gardner, E.S. & McKenzie, E. "Forecasting trends in time series", Management Science 31(10), 1985, 1237–1246: the damped trend.
  • Hyndman, R.J., Koehler, A.B., Ord, J.K., Snyder, R.D. Forecasting with Exponential Smoothing: The State Space Approach, Springer, 2008.
  • Hyndman, R.J. & Athanasopoulos, G. Forecasting: Principles and Practice (3rd ed.), section 8.2 (methods with trend, damped trend) and section 8.3 (Holt-Winters' seasonal method): https://otexts.com/fpp3/holt-winters.html.
  • Difference from the textbook: the coefficients are chosen from a small grid by the in-sample one-step squared error, not by numerical optimisation; it is a little slower and steadier, and cannot fail because an optimiser did not converge.

Use in a module

  1. Save parameters and check history, sample interval, and horizon.
  2. Enable module prediction. Fixed mode runs the selected method; dynamic mode uses centrally enabled methods.
  3. Run rolling backtests and earn version promotion before adoption. Re-run backtests after changes affecting model identity.
  4. Review error, peak underestimation, runtime, and adoption reasons in Observe or Recommend before separately authorizing admission and replica actions.

For insufficient history, invalid settings, timeouts, or invalid output, inspect run reasons. Without eligible forecasts, the module follows its schedules, fallback, and protection rules.
