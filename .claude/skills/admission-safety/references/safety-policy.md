# 安全决策表

| 优先顺序 | 条件 | 资源动作 |
|---|---|---|
| 1 | 全局紧急 bypass | 保留用户原值，固定规则/模型/fallback 都不能覆盖 |
| 2 | Namespace/模块禁止更改 | 保留原值，记录禁止原因 |
| 3 | 启用控制且固定周期匹配 | 只覆盖指定字段，跳过对应模型输出；未填 requests 取合法模块默认值 |
| 4 | 模型快照有效且安全 | 对未固定字段使用建议并执行边界校验 |
| 5 | 模型不可用/样本不足/过期 | 使用已验证模块固定 fallback，显示原因 |
| 6 | 无合法可应用值 | 保留用户原配置，记录拒绝原因 |

Observe 只预测，Recommend 展示，Admission 允许创建时资源变更，Auto 允许唯一 Operator 调副本。开关独立，切换和解除 bypass 需权限审计。

## 数值与快照

逐容器区分 CPU cores/millicores、Memory bytes/Kubernetes Quantity，每 Pod 规格与副本总数分开。校验有限非负、requests≤limits、模块上下界、适用 LimitRange/ResourceQuota。必要约束读取失败不能当作无限额，省略字段不能当零。固定规则同样需校验；旁路仍受 API Server 原有资源合法性校验。

快照应含模块/目标/容器身份、生成/到期时间、策略/模型版本、验证状态及完整性信息。拒绝目标错误、损坏、版本不兼容和过期快照；TTL 有效不意味着数值安全。

保存完整原/建议/应用资源 JSON，不能只保存 patch；准入推荐 ID 与决策/执行审计可关联。非阻塞缓冲需要容量、失败与丢失监测，Kafka 故障不得阻塞准入。

## 固定周期与验收

研究样例：2026-10-01 到 2026-10-20，固定 10 副本、每 Pod CPU Limit 6 核、Memory Limit 24Gi，requests 缺省用合法模块默认值。不是平台默认值。

必须明确 IANA 时区、端点、优先级方向、起止和规则 ID 稳定排序；保存检测冲突，到期恢复算法/默认模式。测试 bypass 高于覆盖、部分字段覆盖、边界前中后、冲突、DST、非法默认 requests、过期/损坏快照、外部服务断连、Webhook 超时与重复调用。

历史 2Gi 而峰值 8Gi 的业务不能仅因 P95 低而推荐 3Gi Limit，保留峰值/OOM 证据；未经授权和安全验证不得自动降 Memory limits。
