# 后端工程约束

## 接口与模块

第三方集成先核实官方文档、SDK 和维护中的成熟开源库；Go 优先适用 Go SDK，确无适用库才手写客户端。按锁定版本核实真实行为，不输出数据无法支持的结论。

任务、采集和通知沿用已有 interface→implementation 与依赖注入模式，按职责组织 type/interface/impl 文件，避免复制框架；不强迫简单 DTO 或局部修复引入无意义接口。

## 数据采集与存储

统一使用现有 GORM ORM、pkg/store 配置和显式迁移入口，兼容 SQLite、MySQL、PostgreSQL，部署选择其中一种；新模型、查询、索引和迁移不能无适配地依赖 PostgreSQL 专有类型或 SQL。系统设置、认证授权、用户、角色、权限、菜单及操作日志复用现有实现，仅做必要增量，不重新建设。
SQLite 连接池只有 1 个连接（`pkg/store`）：开启事务后不要再经全局连接池查询或写入，否则永久等待；casbin 的 `Enforcer.SavePolicy` 就因此死锁，`SyncPolicies` 已改为事务内重写 `casbin_rule`。新增模型表时，同步加入各测试自己的 AutoMigrate 列表（`apiTestDB`、LDAP、DAO 测试各有一份），并在 e2e 里真正走一遍创建/修改接口。

- 每提供方设置请求预算、并发和下载字节上限；默认保守串行，放大并发须有提供方能力与配额依据。预算耗尽等待，不重试风暴。
- 429/403/超时尊重 Retry-After，否则指数退避加抖动，连续失败进入冷却；多个来源隔离预算。
- 使用 gzip 和可识别 User-Agent，需要额度使用正规凭据；不伪装浏览器或轮换 IP 绕过限流。
- Prometheus query_range 按时间分段，限制点数、并发、缓存和保留期，记录缺样、延迟、NaN、跳变及粒度；不得静默换源混合真值。
- 优先紧凑存储和合理压缩，避免不必要冗余，但完整原始/应用资源、预测特征和审计证据按领域契约保留。
- 字段类型按真实范围、增长和跨数据库兼容性选择；不能为了更小类型截断 ID，不能将所有 varchar 机械改成 char。

## 生命周期与交付

沿用 pkg/cmd：all 组合运行，单模块入口只启动自身必要依赖；当前 CLI 名为 kube-resource-fcst，collector 等是规划入口，不能当成现有命令。可执行产物置于 target/bin。

原研究提出整体覆盖率 65%、单文件 80% 的目标；涉及代码实施时按实际测试范围提供证据，不能把目标当现状，也不为文档修改写应用测试。前后端契约同步，迁移显式执行，按功能整理变更。

技能统一维护在 .agents/skills；不使用旧交易项目的绝对路径、quant-progress、.claudes 镜像或已失效 sync-skill.sh 流程。提交不得夹带用户无关改动，不自动推送或重写远端
