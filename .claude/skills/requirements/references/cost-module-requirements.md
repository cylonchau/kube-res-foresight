# 独立成本模块需求表（暂缓，2026-11-19）

状态：**只有需求表，不开发。** 用户 2026-11-19 决定：成本相关内容暂时移出当前阶段（[P10 资源超配分析](overprovision-p10.md)），待这张表确认后再做，并且不影响超配分析。此前做过的 P9 C1～C4（见 [cost-closure-p9.md](cost-closure-p9.md)）是这张表里一部分内容的早期实现，现在暂缓。

## 目标与边界

| 项 | 内容 |
|---|---|
| 目标 | 在保证稳定性的前提下，用更低的实际基础设施成本承载负载，并能证明省了多少 |
| 不做 | 当前阶段不做；不把 Requests 降幅当成本节省；不引入 HPA 当执行后端（副本只由 operator 控制）；不 cordon/drain/删节点（节点由 Karpenter 或集群自动伸缩管） |
| 前置 | P10 的 A1（集群与工作负载的采集与持久化）和 A2（超配分析）；没有它们，成本模块没有可靠的“释放了什么” |
| 为什么独立 | 成本要价格、账单、基线，数据来源和口径与资源分析不同；混在一起会让“资源释放”被误读成“省钱” |

## 字段

| 字段 | 含义 | 来源 | 计算依据 | 实现方式 | 待确认 |
|---|---|---|---|---|---|
| 节点每小时价格 | 一类节点一小时多少钱 | 价格规则或 OpenCost | 取优先级最高的匹配规则；没有匹配的节点是“未定价”，不当免费 | 价格表，纯函数匹配 | 价格怎么随 Region、可用区、实例规格变化 |
| 币种 | 金额的币种代码 | 价格规则 | 不同币种分块，不相加 | 币种字段 | 默认币种 |
| 计费模式 | 按需、预留、Spot、Savings Plan | 价格规则或账单 | 有折扣的节点用折后价 | 规则里加字段 | 是否需要，折扣怎么来 |
| 节点小时 | 节点实际运行了多久 | 集群清单的快照 | 相邻快照之间节点存在则累计 | 从 A1 的快照积分 | 快照周期够不够细 |
| CPU 与内存的分摊比例 | 节点价格多少算在 CPU，多少算在内存 | 系统参数 | 默认 50%：是假设，不是测量 | 系统参数 | 按你们供应商的核价与 GiB 价比设置 |
| 工作负载成本 | 一个工作负载占了多少节点价格 | Requests 与节点价格 | 节点价格的 CPU 部分按 CPU Requests 占节点可分配 CPU 的比例分摊，内存部分同理 | 纯函数，守恒：Σ工作负载 + 闲置 = 节点价格 | 是否按实际使用而不是 Requests 分摊（OpenCost 有两种） |
| 闲置成本 | 没被 Requests 占用的部分 | 同上 | 节点价格 − Σ工作负载成本 | 同上 | 闲置算谁的 |
| 共享成本 | 控制面、系统命名空间、DaemonSet 的成本 | 集群清单 | 按比例摊给业务，或单列 | 待定 | 摊不摊，怎么摊 |
| 存储、网络、GPU 成本 | 除 CPU 与内存外的费用 | 账单或 OpenCost | 各自的单价与用量 | 暂不做 | 要不要 |
| 月度成本 | 一个月的估算 | 小时价格 | 小时价格 × 730 | 页面口径，写明 730 | 是否按实际天数 |
| 资源释放量 | Requests 的前后之差乘时间 | P10 的配置变化历史 | `Σ(前 − 后) × 时长`，单位 vCPU·小时、GiB·小时 | 从配置历史算 | 无 |
| 预计节省 | 释放量折价，或模拟能少几台节点 | 价格表与装箱模拟 | 释放量 × 单价；或可释放节点数 × 节点价格 | 页面标“预计” | 无 |
| 成本避免量 | 未来少扩容省的钱 | 需要增长假设 | 增长趋势的外推 | 单列，不进总 KPI | 要不要做，假设怎么给 |
| 实际节省 | 与基线比，经核实的成本下降 | 节点小时或账单 | 节点数确实下降且价格已知时，`基线成本 − 现在成本`，按负载变化归一化 | 节省台账 | 基线窗口；负载变了怎么算 |
| 基线 | 比较用的优化前状态 | 优化生效前的窗口 | 默认优化前 14 天，同时记录负载量 | 台账字段 | 窗口多长 |

## 计算依据（P9 已定、已验证过逻辑的部分）

| 项 | 依据 | 验证 |
|---|---|---|
| 成本分摊守恒 | 单位价格 = 节点价格 × 权重 ÷ 可分配量；Pod 成本 = Requests × 单位价格；Requests 超过可分配时按比例缩到节点价格 | 单测，合成数据 |
| 四个财务口径 | 资源释放量、预计节省、成本避免量、实际节省不混用；“已实现”必须有节点小时或账单依据 | 文档约定；台账未做 |
| 节点装箱模拟 | 最少用的节点先试，Pod 从大到小放最紧的节点；DaemonSet 跟节点走；没有控制器的 Pod 挡住节点；污点用子集关系近似 | 单测；**结果只是估计**：没模拟的约束让它偏多，贪心让它偏少，既不是上界也不是下界 |
| 金额 | 只在有价格规则和已读到的集群时才有；没有就只给资源量，写明原因 | 单测 |
