Combination · 组合预测

对多个成员的预测逐步取中位数，或按近期误差加权。组合本身也需要回测晋升，不默认优于单个成员。

← 算法与模型总览

用途与适用负载

对多个成员的预测逐步取中位数，或按近期误差加权。组合本身也需要回测晋升，不默认优于单个成员。

历史数据与运行条件

至少满足一个成员；不够历史的成员会被省略。误差加权还需要额外回看窗口，实际要求随成员和预测视野增加。

输入应是等间隔、无缺口且数值有限的序列。输出保留输入指标单位，例如 CPU 核、内存字节或每秒请求数；采样步长决定步数对应的真实时间。最低样本数仅表示可运行，不代表预测可靠。

此方法不使用协变量；分别预测各目标指标。

原理与公式

组合预测把几种不同的算法放在一起：每一步取它们预测的中位数，或者按各自最近的表现加权平均。一个在某一方面犯错的成员，会被其他成员“投票”压住；它不需要训练。

公式
成员：    f(k)(h) = 成员 k 对第 h 步的预测（每个成员用它自己的默认参数，在同一份历史上运行）

mode = median：        ŷ(h) = 各成员 f(k)(h) 的中位数

mode = inverse_error： ŷ(h) = Σ w(k) · f(k)(h) / Σ w(k)
  成员误差 e(k)：把历史在最近 error_windows 个“预测范围”处截断，让成员重新预测并与实际比较，
                 再加上最近 recent_steps 步；取绝对误差的平均，成员预测低于实际（短缺）时该误差乘 under_weight
  eps  = 0.001 × 历史绝对值的平均 + 10⁻¹²            （防止某个成员误差恰好为 0 而独占全部权重）
  剔除：e(k) > trim_ratio × min(e) + eps  的成员，权重为 0
  权重：w(k) = ( 1 / (e(k) + eps) ) ^ sharpness

参数怎样进入公式：

  • members：成员的算法 id，2 到 6 个，逗号分隔（默认 ewma,holt_winters,theta）。成员用默认参数运行，所以只有不需要必填参数的算法能当成员（ewma、holt_winters、theta、hist_percentile、naive、knn 等）；不能把组合自己当成员，也不能重复。成员需要的历史比现有的多时，它被排除在这一次预测之外。
  • mode：inverse_error（按误差加权，默认）或 median（中位数）。
  • error_windows（默认 4）：用多少个预测范围来测成员的误差。
  • under_weight（默认 2）：成员预测低于实际时，误差算几倍。和平台给算法打分的口径一致：资源不够比多给更糟。
  • sharpness（默认 2）：权重是误差倒数的几次方。越大越偏向最近最准的成员。
  • trim_ratio（默认 3）：误差超过最好成员 3 倍的成员被排除；0 表示不排除。
  • recent_steps（默认 3）：再把最新的几步算进误差，让刚刚跟上变化的成员比一小时前才对的成员更有分量。

为什么这样做：预测竞赛（M4）的结论是：把不同类型的模型组合起来，很难被单个模型击败。一个成员在某个形态上错了，其他成员会把它拉回来；而且几乎没有训练成本。按近期误差加权，则让组合更靠近最近一直对的成员，而不是把一个最近一直错的成员平均进来。

要留意：组合本身也是一个算法，同样要回测、评分、晋升，不会因为它是“多个算法的组合”就被默认采用。成员的参数不读取算法页上为各成员设置的值，只用默认参数。

参数 / 类型默认值 / 范围 / 单位含义与使用
members
string		"ewma,holt_winters,theta"
无额外范围限制		成员算法的 id，用逗号分隔，2 到 6 个，如 ewma,holt_winters,theta。只能选不需要必填参数的算法（ewma、holt_winters、theta、hist_percentile、knn、naive 等），不能选 combination 自己。成员按各自的默认参数运行，不读取算法管理页里给它们设置的参数。
mode
string		"inverse_error"
inverse_error / median		inverse_error = 按每个成员在这个负载最近几个窗口里的平均绝对误差的倒数加权；median = 每一步取成员预测的中位数。
error_windows
int		4
≥ 1; ≤ 20		测各成员误差用最近多少个预测视野；越多越稳，也越慢。仅 mode=inverse_error 时使用，历史不够时按等权。
under_weight
float		2
≥ 1; ≤ 5		量成员误差时，预测低于实际的部分算几倍（与评分里“少给比多给代价更大”的倍数一致）。1 = 普通平均绝对误差；默认 2，使组合偏向少给得少的成员。仅 mode=inverse_error 时使用。
sharpness
float		2
≥ 1; ≤ 6		权重 = (1/误差) 的这个次方。1 = 与误差成反比（最差的成员仍占相当的权重）；越大越偏向最近最好的成员，6 接近只选最好的。默认 2。仅 mode=inverse_error 时使用。
recent_steps
int		3
≥ 0; ≤ 20		除了最近几个预测视野，再把最新的这几步也算进成员的误差：刚刚跟上一次变化的成员比一小时前才对的成员更值得信。0 = 不算。默认 3。仅 mode=inverse_error 时使用。
trim_ratio
float		3
≥ 0; ≤ 20		误差超过最好成员这个倍数的成员不参与（权重为 0）。0 = 不剔除；默认 3。仅 mode=inverse_error 时使用，历史不够时所有成员按等权。

配置示例

在“算法管理”编辑参数。以下仅为参数对象，不是 config.yaml 全文；周期示例按 5 分钟采样，需按实际步长调整。未列出的可选参数使用上表默认值。

JSON
{
  "members": "ewma,holt_winters,theta",
  "mode": "inverse_error",
  "error_windows": 4,
  "under_weight": 2,
  "sharpness": 2,
  "recent_steps": 3,
  "trim_ratio": 3
}

调参与取舍

members 是逗号分隔的 2～6 个 ID，成员必须可用默认参数构建，不能包含 combination。成员不读取算法管理中各自保存的参数。under_weight 增大对低估的惩罚；sharpness 越大越偏向表现好的成员。

来源与引用

  • Bates, J.M. & Granger, C.W.J. “The combination of forecasts”，Operational Research Quarterly 20(4)，1969，451–468：预测组合的开创性论文，权重取各预测误差的倒数的思路来自这里。
  • Makridakis, S.、Spiliotis, E.、Assimakopoulos, V. “The M4 Competition: 100,000 time series and 61 forecast methods”，International Journal of Forecasting 36(1)，2020，54–74：组合方法在 M4 竞赛中表现最好。
  • Timmermann, A. “Forecast combinations”，Handbook of Economic Forecasting 第 1 卷，2006，135–196：预测组合的综述。
  • “短缺乘 under_weight”“误差 3 倍以上的成员剔除”“把最新几步算进误差”是本平台为了与算法评分口径一致、并更快跟上变化而加入的处理，不在上述原始论文里。

通用参数：变化重置与分位校准

参数 / 类型默认值 / 范围 / 单位含义与使用
reset_on_change
bool		false
无额外范围限制		水平突变后重置：检测历史里最后一次水平突变（发布、扩缩容、流量切换），只用突变之后的历史预测。关闭时用全部历史（现状）。突变之后至少要有 6 步才会被确认；突变后的历史不够算法所需时，取算法所需的最新一段。
change_threshold
float		8
≥ 3; ≤ 50		突变阈值：突变幅度（扣除前一段趋势后）超过噪声的多少倍才算，越大越不容易误报，噪声由相邻步变化的稳健标准差估计。仅 reset_on_change=true 时使用。
change_min_shift
float		0.2
≥ 0; ≤ 5		最小突变幅度：突变至少是水平的这个比例（0.2 = 20%），很干净的序列上的微小跳变不算。仅 reset_on_change=true 时使用。
quantile_level
float		0
≥ 0; ≤ 0.99		推荐分位数：0 = 点预测（现状）；0.9 等 = 预测「实际值有约 90% 的把握不超过」的线（保形预测：用本算法在这个负载最近几个窗口里的真实误差校准，需要更多历史和时间）。必须大于 0.5。
calibration_windows
int		8
≥ 3; ≤ 50		校准窗口数：用最近多少个历史窗口测本算法的误差；越多越稳，也越慢（每个窗口多跑一次预测）。仅推荐分位数大于 0 时使用。

quantile_level 是 0～1 的分位点，percentile 是 1～100 的百分数，二者不是同一参数。分位校准会额外运行历史预测；增加校准窗口前检查历史与运行预算，覆盖率是评估目标而非保证。

在模块中使用

  1. 保存参数，检查历史窗口、采样步长和预测范围。
  2. 打开模块的“启用预测”；固定算法只运行指定方法，动态算法使用平台已启用的方法。
  3. 先运行滚动回测，通过版本晋升后才会采用；修改影响模型版本的参数后重新回测。
  4. 在仅观察或仅推荐下检查误差、峰值低估、耗时与采用原因，再分别授权准入和副本执行。

历史不足、参数不合法、运行超时或输出无效时，检查算法运行原因；没有合格预测时按模块的固定周期、兜底与保护规则处理。
