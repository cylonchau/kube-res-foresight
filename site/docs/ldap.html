使用指南

LDAP 登录配置

配置目录登录、取组方式和角色映射，并沿用其他系统已有的 LDAP 设置。

登录怎么判断本地还是目录用户

登录页没有“来源”选项，平台按用户名在本地库里的情况决定：

情况处理
本地库有这个用户名，来源是本地只校验本地密码，不访问目录。admin 因此在目录不可用时仍能登录。
本地库有，来源是 LDAP只向目录校验密码。
本地库没有，LDAP 已启用向目录认证；通过后按角色映射得出角色，并自动创建 LDAP 用户。
本地库没有，LDAP 未启用登录失败。

目录里与本地账号同名的用户不会接管本地账号。LDAP 用户在本地的密码是随机值，无法用于本地登录，也不能在个人中心修改密码，请在目录中修改。用户列表和个人中心会显示账号来源。

参数

在“系统管理 → 系统参数”的 LDAP 分类里逐项设置，每项单独保存。

参数含义
ldap.url目录地址，如 ldaps://ldap.example.com:636。使用 ldap:// 时必须开启 StartTLS。
ldap.start_tls / ldap.skip_verifyStartTLS；是否跳过证书校验。能提供 CA 时不要跳过。
ldap.ca_cert自签名证书的 CA（PEM）。保存后只显示掩码。
ldap.bind_dn / ldap.bind_password用于查询用户的服务账号。密码加密保存，必须先设置 bind DN。
ldap.user_base_dn搜索用户的起点，如 dc=example,dc=com。
ldap.user_filter查找用户的过滤器，必须恰好含一个 %s（登录名），如 (cn=%s) 或 (&(objectClass=person)(uid=%s))。
ldap.display_name_attr / email_attr / phone_attr显示名、邮箱、电话对应的属性，每次登录刷新。
ldap.member_of_attr用户条目上列出所属组 DN 的属性，通常是 memberOf。设置后直接读取它取组。
ldap.group_base_dn / ldap.group_filter不使用 memberOf 时，到组条目里查成员：过滤器里 %s 是用户 DN，%u 是登录名，如 (member=%s)。两项要一起有或一起空：设置其中一项而另一项为空时会自动补上常用值，清空其中一项会一起清空。
ldap.group_name_attr组条目里作为组名的属性，默认 cn。
ldap.group_role_mappings组到角色的映射，见下节。
ldap.default_role_code不在任何映射组里的用户使用的角色。留空则这些用户无法登录。
ldap.timeout_seconds连接和查询超时，1 到 120 秒。
ldap.enabled是否启用目录登录。

启用时平台会校验整套配置并连接目录检查一次，不通过就拒绝启用并说明原因，所以请把 ldap.enabled 放在最后设置。

取组的两种方式

二选一，也可以同时使用，结果合并。

  • 读用户的 memberOf：设置 ldap.member_of_attr，不需要组基础 DN 和过滤器。每个值（组的 DN）既可以按完整 DN 匹配，也可以按 DN 第一段的值匹配（cn=ops,ou=groups,… 对应 ops）。
  • 到组条目里查成员：设置 ldap.group_base_dn、ldap.group_filter，用 ldap.group_name_attr 取组名。常见写法：OpenLDAP 的 groupOfNames 用 (member=%s)；posixGroup 用 (memberUid=%u)；AD 需要包含嵌套组时用 (member:1.2.840.113556.1.4.1941:=%s)。

角色映射

ldap.group_role_mappings 每行一条，格式为 组=角色编码：

ops=ADMIN
dev=VIEWER
ou=sre,ou=平台组,dc=example,dc=com=ADMIN
  • 左边是组名（cn）或完整 DN，不区分大小写；完整 DN 里的空格要与目录返回的一致。
  • 右边是角色的编码，在“授权管理 → 角色”里查看。角色必须存在并已启用。
  • 程序按最后一个 = 切分，所以完整 DN 的写法可以直接用。一个组可以写多行授予多个角色。用户属于多个组时取角色的并集。
  • 以 # 开头的行是注释，空行忽略。格式不对或重复的行在保存时被拒绝。

用户不在任何映射组里时使用 ldap.default_role_code；两者都没有就拒绝登录。已存在的 LDAP 用户如果失去所有角色，会被停用并结束其会话。

沿用已有的 LDAP 配置

公司里其他系统（Wiki、代码仓库、监控、CI 等）通常已经接入了同一个目录，它们的 LDAP 设置里已有这里需要的信息。照下表把已有的值填到对应参数即可：

已有的信息填到
服务器地址、端口、是否 SSLldap.url，SSL 写成 ldaps://地址:端口
是否 StartTLS、是否跳过证书校验ldap.start_tls、ldap.skip_verify
查询用的账号（Bind DN）和密码ldap.bind_dn、ldap.bind_password
用户搜索范围（Base DN）ldap.user_base_dn
用户搜索过滤器，其中登录名的占位符ldap.user_filter，占位符统一写成 %s。例如 (cn=${username})、(uid={0})、(sAMAccountName=%(user)s) 都写成 (cn=%s) 这类形式
姓名、邮箱的属性名ldap.display_name_attr、ldap.email_attr
用户条目里记录所属组的属性（常叫 memberOf）ldap.member_of_attr
组的搜索范围和成员过滤器（没有 memberOf 时）ldap.group_base_dn、ldap.group_filter
“组的 DN → 角色/权限”的对应表ldap.group_role_mappings，每条写成 组 DN=本平台的角色编码

其他系统里的角色（管理员、编辑、只读等）和本平台的角色没有固定对应，请改用你在“授权管理 → 角色”里建好的角色编码。平台自带的管理员角色编码是 ADMIN，拥有全部权限，授予整个组之前先确认。

完整配置示例与一次登录的过程

下面用两个常见目录，把每个参数具体填什么、一次登录里平台做了什么，放在一起看。地址、DN 和组名都是示例，请换成你们目录里的值。

示例一：OpenLDAP，用组条目里的成员关系取组

目录里有：

LDIF
dn: uid=alice,ou=people,dc=example,dc=com
uid: alice
cn: Alice Zhang
mail: alice@example.com

dn: cn=sre,ou=groups,dc=example,dc=com
objectClass: groupOfNames
cn: sre
member: uid=alice,ou=people,dc=example,dc=com

系统参数这样填（“系统管理 → 系统参数 → LDAP 认证”，每项单独保存，最后再启用）：

参数值说明
ldap.urlldaps://ldap.example.com:636用 LDAPS；如果用 ldap://，必须开 StartTLS。
ldap.bind_dncn=readonly,dc=example,dc=com只读的服务账号，用来搜索用户。
ldap.bind_password服务账号的密码加密保存。
ldap.user_base_dnou=people,dc=example,dc=com从这里往下搜索用户。
ldap.user_filter(uid=%s)%s 会被替换成登录名。
ldap.display_name_attrcn显示名。
ldap.email_attrmail邮箱。
ldap.group_base_dnou=groups,dc=example,dc=com到这里搜索组条目。
ldap.group_filter(member=%s)这里的 %s 是用户的 DN，不是登录名。
ldap.group_name_attrcn（默认）组条目里作为组名的属性。
ldap.group_role_mappings
sre=ADMIN
dev=VIEWER
每行 组=角色编码。
ldap.default_role_code留空不在映射组里的人无法登录。想让他们以只读登录，填一个只读角色的编码。
ldap.enabledtrue最后设置：启用时平台会校验整套配置并连一次目录。

alice 登录时发生了什么：

  1. 平台用 LDAPS 连接目录，并用服务账号 cn=readonly,… 登录。
  2. 在 ou=people,… 下用 (uid=alice) 搜索。找到一条 uid=alice,ou=people,dc=example,dc=com；一条也没有是“用户不存在”，多于一条会被拒绝（过滤器必须只匹配一个人）。输入的登录名里的特殊字符会被转义，不能用来改写过滤器。
  3. 用这个 DN 和 alice 输入的密码再登录一次。密码只由目录校验，平台不保存也不比较。
  4. 读取 cn 和 mail，得到显示名 Alice Zhang 和邮箱。
  5. 取组：在 ou=groups,… 下用 (member=uid=alice,ou=people,dc=example,dc=com) 搜索，找到组 cn=sre，组名是 sre。
  6. 按角色映射 sre=ADMIN，alice 得到 ADMIN 角色；本地库里没有 alice，所以自动创建一个来源为 LDAP 的用户并登录。

示例二：Active Directory，直接读 memberOf

参数值
ldap.urlldaps://ad.example.com:636
ldap.bind_dnCN=svc-krf,OU=Service Accounts,DC=example,DC=com
ldap.user_base_dnDC=example,DC=com
ldap.user_filter(&(objectClass=user)(sAMAccountName=%s))
ldap.display_name_attr / ldap.email_attrdisplayName / mail
ldap.member_of_attrmemberOf
ldap.group_base_dn / ldap.group_filter留空（用 memberOf 就不需要）
ldap.group_role_mappings
Platform-Admins=ADMIN
CN=Platform-Readers,OU=Groups,DC=example,DC=com=VIEWER

AD 用户条目的 memberOf 里是每个组的完整 DN，例如 CN=Platform-Admins,OU=Groups,DC=example,DC=com。映射左边既可以写完整 DN，也可以只写第一段的值（Platform-Admins），平台两种都会匹配。第二行展示了完整 DN 的写法：程序按最后一个 = 切分，前面的整个 DN 不受影响。需要把嵌套组也算进来时，不用 memberOf，改用组过滤器 (member:1.2.840.113556.1.4.1941:=%s)。

启用前先自查

  • 服务账号能搜到用户：用任何 LDAP 客户端以它登录，对 user_base_dn 用同样的过滤器查一个已知用户，应当恰好返回一条。
  • 角色编码存在且已启用：映射右边的编码要和“授权管理 → 角色”里的一致。
  • 先试普通用户再试管理员：确认映射的角色不会把不该有的权限给了整个组。

同步与停用

目录里被删除、被禁用或不再属于任何映射组的用户，会在同步时被停用并结束会话；目录重新启用的用户会恢复，被管理员手动停用的除外。目录不可达时不会改动任何账号，避免一次故障把所有人锁在外面。

排查

现象检查
无法启用，提示目录检查失败地址和端口、证书（自签名需要 CA 或暂时跳过校验）、服务账号和密码、网络是否通。
登录失败，页面只显示用户名或密码错误看平台日志中的 ldap login refused，reason 写明具体原因。
the user belongs to no group mapped to a role认证已通过，但没有角色。括号里的 groups found 是目录返回的组：为空说明取组方式或过滤器不对；有组名则补映射或设置默认角色。
a local account with this name exists本地已有同名账号，目录不会接管它；改用本地密码，或让管理员处理这个账号。
某一项保存被拒绝启用状态下每次修改都会校验整套配置。必填项（地址、用户基础 DN、用户过滤器）不能留空；bind DN 与密码要成对。

本地账号始终可以用本地密码登录，目录不可用不影响它们。
