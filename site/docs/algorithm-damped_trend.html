使用指南

Damped Trend · 短窗口趋势加阻尼

从最近一小段历史估计已经开始的缓慢爬升会走到哪里，斜率逐步衰减、预测向上限收敛。适合内存、缓存这类缓慢爬升夹杂突然下降的负载。

← 算法与模型总览

用途与适用负载

从最近一小段历史估计一个已经开始的缓慢爬升会走到哪里：水平取 EWMA，斜率取最近几步里各点两两斜率的中位数，斜率只延续越来越少的步数（阻尼），预测向一个上限收敛而不是无限外推。适合缓慢爬升、夹杂突然下降（重启、垃圾回收）的负载，例如内存和缓存；不需要周期，几十个样本就能开始工作。

它看不到上涨开始之前的突发，也不认识日周期：没有先兆的突发要靠预留容量，周期性的高峰要看季节类算法（它们需要足够多个周期的历史才能参与决策）。它是候选算法，要在回测里胜过基线才会被采用。

历史数据与运行条件

至少 window_steps 个点（默认 12，最少 3）。

输入应是等间隔、无缺口且数值有限的序列。输出保留输入指标单位，例如 CPU 核、内存字节或每秒请求数；采样步长决定步数对应的真实时间。最低样本数仅表示可运行，不代表预测可靠。

此方法不使用协变量；分别预测各目标指标。

原理与公式

阻尼趋势回答的是“一个已经开始的缓慢爬升会走到哪里”。水平取 EWMA，斜率取最近一小段里各点两两斜率的中位数，斜率只延续越来越少的步数，所以预测向一个上限收敛而不是无限外推。

公式
水平：  ℓ = 对全部历史做 EWMA（系数 α，从第一个值起递推）
斜率：  b = 最近 window_steps 个点里所有点对斜率 (y(j) − y(i)) / (j − i) 的中位数（Theil-Sen）
        若 b < 0：b ← b × down_share
预测：  ŷ(T+h) = ℓ + b · (φ + φ² + … + φʰ)               φ = damping
        并限制在 ≤ cap_ratio × 窗口内最高值，且不小于 0

φ < 1 时，无论 h 多大，预测最远只会到  ℓ + b · φ / (1 − φ)

参数怎样进入公式：

  • alpha：水平的 EWMA 系数。
  • window_steps：斜率取自最近多少步（默认 12，也是最少样本数）。越短越快反映刚开始的上涨，也越容易受噪声影响。
  • damping（φ）：阻尼。斜率每向前一步乘一次 φ。默认 0.9 时预测最远走到 ℓ + 9·b；1 表示不阻尼，按直线一直外推。
  • down_share：下降的斜率跟随多少。0（默认）表示不跟随：预测在下降时只是平推，不催着降容量；是否缩容是决策的事，决策有自己的保持时间。
  • cap_ratio：预测不超过窗口内最高值的这个倍数，防止很陡的短斜率被外推到很远。

为什么这样做：内存和缓存经常“缓慢爬升，夹杂突然下降（重启、垃圾回收）”。用全部历史拟合直线会被突降拉歪；只看水平又总是落后于爬升。取中位数斜率，一两个孤立的尖峰或一次骤降不会移动它；再对斜率做阻尼，是因为短窗口里的斜率不会永远持续，让预测向上限收敛，比直线外推更诚实。

它做不到的：看不到上涨开始之前的突发，也不认识日周期。没有先兆的突发要靠预留容量；周期性高峰要看季节类算法。它是候选算法，要在回测里胜过基线才会被采用。

参数说明

窄屏可左右滑动参数表，查看完整说明。

参数 / 类型默认值 / 范围 / 单位含义与使用
alpha
float		0.3
≥ 0.001; ≤ 1		水平的 EWMA 系数，越大越贴近最新值；取值 (0,1]。
window_steps
int		12
≥ 3; ≤ 1000; steps		斜率取自最近多少步。越短越快反映刚开始的上涨，也越容易受噪声影响；按采样步长换算成时间，例如 30 秒步长的 12 步是 6 分钟。也是算法的最少样本数。
damping
float		0.9
≥ 0.01; ≤ 1		阻尼系数 φ：斜率每往前一步乘一次 φ，预测最远走到水平 + 斜率·φ/(1−φ)。1 表示不阻尼（按直线外推，会一直上涨）；越小越快收敛。
down_share
float		0
≥ 0; ≤ 1		下降的斜率跟随多少：0 = 不跟随（预测按水平平推，给出容量要慢），1 = 完全跟随。何时降下来是决策的事，这里默认不催它。
cap_ratio
float		1.5
≥ 1; ≤ 10		预测不超过最近窗口最高值的这个倍数，防止很陡的短斜率被外推到很远。

配置示例

在“算法管理”编辑参数。以下仅为参数对象，不是 config.yaml 全文；窗口按 30 秒采样，需按实际步长调整。未列出的可选参数使用上表默认值。

JSON
{
  "alpha": 0.3,
  "window_steps": 12,
  "damping": 0.9,
  "down_share": 0,
  "cap_ratio": 1.5
}

计算示例：数据、参数与代入过程

一个缓慢爬升的内存（GiB），每 5 分钟一个点，其中夹着两次小的回落。参数取默认值，只把窗口缩成 6 步以便手算。

JSON
{
  "alpha": 0.3,
  "window_steps": 6,
  "damping": 0.9,
  "down_share": 0,
  "cap_ratio": 1.5
}
数据
y = [50, 51, 53, 52, 55, 57, 56, 59]        n = 8

第 1 步，水平 ℓ（对全部 8 个点做 EWMA，α = 0.3）：

计算
50 → 0.3×51+0.7×50 = 50.3 → 0.3×53+0.7×50.3 = 51.11 → 51.377 → 52.4639 → 53.8247 → 54.4773 → 0.3×59+0.7×54.4773 = 55.8341
ℓ = 55.8341

第 2 步，斜率 b（最近 6 个点 [53, 52, 55, 57, 56, 59] 的点对斜率中位数）。6 个点共 15 对，逐对算 (y(j)−y(i))/(j−i)，从小到大排：

计算
−1, −1, 0.5, 0.75, 1, 1, 1.2, 1.3333, 1.3333, 1.3333, 1.75, 2, 2.5, 3, 3
第 8 个（中位数） = 1.3333
b = 1.3333（每步）

注意窗口里的回落（53→52、57→56）算出来的负斜率 −1 排在最前面，没有影响中位数，这就是“中位数对孤立的骤降不敏感”。

第 3 步，代入公式（φ = 0.9，累计的阻尼步长 φ+φ²+…）：

hφ + … + φʰŷ = ℓ + b × 累计
10.955.8341 + 1.3333×0.9 = 57.0341
20.9 + 0.81 = 1.7155.8341 + 1.3333×1.71 = 58.1141
31.71 + 0.729 = 2.43955.8341 + 1.3333×2.439 = 59.0861

结果 [57.0341, 58.1141, 59.0861]，增量一步比一步小（1.20、1.08、0.97）。无论预测多远，最高也只到 55.8341 + 1.3333 × 9 = 67.83；上限 cap_ratio × 窗口最高值 = 1.5 × 59 = 88.5，此例中阻尼先起作用，cap 没有触发。

把 damping 改成 1（不阻尼），同样的数据每步都多 1.3333，预测会一直上升，直到被 88.5 的上限拦住。

这些数字由 pkg/forecast/docs_examples_test.go 用真实代码算出并持续校验。

调参与取舍

窗口越短，越快跟上刚开始的上涨，也越容易被噪声带偏；中位数斜率对一两个孤立的尖峰或骤降不敏感，但窗口里大部分点都在波动时斜率就不可靠。阻尼越小预测收敛得越近，保守地低估持续上涨；阻尼接近 1 会走得很远，由 cap_ratio 兜住。down_share 保持 0 时，预测在负载下降时只是平推，什么时候缩容由决策里的保持时间和冷却决定。

来源与引用

  • Gardner, E.S. & McKenzie, E. “Forecasting trends in time series”，Management Science 31(10)，1985，1237–1246：阻尼趋势，趋势每一步衰减以免外推过头。
  • Gardner, E.S. “Exponential smoothing: The state of the art—Part II”，International Journal of Forecasting 22(4)，2006，637–666：回顾并推荐阻尼趋势作为稳健的默认。
  • Theil（1950）、Sen（1968）：斜率取点对斜率的中位数，见 峰值包络 页。
  • 本算法把“EWMA 水平 + 窗口内中位数斜率 + 阻尼 + 下降只跟随一部分 + 上限”组合起来，是针对“缓慢爬升夹杂骤降”的负载设计的，不是某一篇论文的原样算法。

通用参数：变化重置与分位校准

参数 / 类型默认值 / 范围 / 单位含义与使用
reset_on_change
bool		false
无额外范围限制		水平突变后重置：检测历史里最后一次水平突变（发布、扩缩容、流量切换），只用突变之后的历史预测。关闭时用全部历史（现状）。突变之后至少要有 6 步才会被确认；突变后的历史不够算法所需时，取算法所需的最新一段。
change_threshold
float		8
≥ 3; ≤ 50		突变阈值：突变幅度（扣除前一段趋势后）超过噪声的多少倍才算，越大越不容易误报，噪声由相邻步变化的稳健标准差估计。仅 reset_on_change=true 时使用。
change_min_shift
float		0.2
≥ 0; ≤ 5		最小突变幅度：突变至少是水平的这个比例（0.2 = 20%），很干净的序列上的微小跳变不算。仅 reset_on_change=true 时使用。
quantile_level
float		0
≥ 0; ≤ 0.99		推荐分位数：0 = 点预测（现状）；0.9 等 = 预测「实际值有约 90% 的把握不超过」的线（保形预测：用本算法在这个负载最近几个窗口里的真实误差校准，需要更多历史和时间）。必须大于 0.5。
calibration_windows
int		8
≥ 3; ≤ 50		校准窗口数：用最近多少个历史窗口测本算法的误差；越多越稳，也越慢（每个窗口多跑一次预测）。仅推荐分位数大于 0 时使用。

quantile_level 是 0～1 的分位点，percentile 是 1～100 的百分数，二者不是同一参数。分位校准会额外运行历史预测；增加校准窗口前检查历史与运行预算，覆盖率是评估目标而非保证。

在模块中使用

  1. 保存参数，检查历史窗口、采样步长和预测范围。
  2. 打开模块的“启用预测”；固定算法与其他已启用的算法一起运行，只有指定的决定推荐，动态算法使用平台已启用的方法。
  3. 先运行滚动回测，通过版本晋升后才会采用；修改影响模型版本的参数后重新回测。
  4. 在仅观察或仅推荐下检查误差、峰值低估、耗时与采用原因，再分别授权准入和副本执行。

历史不足、参数不合法、运行超时或输出无效时，检查算法运行原因；没有合格预测时按模块的固定周期、兜底与保护规则处理。
