使用指南

集群大盘与 Operator 上报

声明集群指标、区分模块指标与集群指标，并了解 Operator 上报给平台的集群与工作负载信息。

集群大盘：每一项都要先声明

“预测结果 > 集群大盘”显示一个集群的节点、Pod、CPU 和内存。大盘不内置任何查询：显示的每一项都必须在“指标模板”里声明，没有声明的项目不会去查，也不会用别的查询代替；页面会列出还没声明的指标。

  1. 新建指标模板，指标类型选“集群指标”，数据源选这个集群的 Prometheus。可以用预设一键创建。
  2. 每个声明了集群指标的 Prometheus 数据源就是一个集群；系统参数 cluster.datasource_id 指的那一个是默认集群。
  3. 在集群大盘选择集群，查看节点、Pod、CPU 与内存。

模块指标与集群指标

类型谁使用说明
模块指标模块的指标来源、资源大盘模块从这里选指标。分为参与算法的指标，和只用来展示的指标（Requests、Limits、OOM、JVM、限流等）。
集群指标集群大盘模块不能选它。

模块指标要说明查询结果是“单 Pod”还是“全副本总和”。查询对每个 Pod 返回一条序列时，平台提示怎样合并：求总和用 sum(...)，求单 Pod 用 avg(...) 或 max(...)。模板名称与查询明显不符时（例如名称写 Limits、查询的是 requests），平台会指出。

Operator 上报：集群里的真实配置

Operator 以只读方式读取集群，并上报给平台：

  • 节点：是否就绪、能否调度、容量与可分配量，以及这个模块的 Pod 在节点上的 Requests、Limits 之和（只统计模块的 Pod，不读其他 Pod）。
  • 模块的工作负载：期望、就绪、可用、已更新的副本数；每个容器的 Requests 与 Limits；Pod 列表（名称、节点、阶段、是否就绪、重启次数）；以及是否有 HPA 或 KEDA 在控制它。

Operator 约每 5 分钟读取一次；平台保存最新一次，并记录配置的变化（保留得比快照更久）。资源大盘把它当作单 Pod 的 Requests、Limits、当前副本数、集群名和 Pod 名的来源；超过 15 分钟的上报不再当作“现在”。没有上报时，大盘退回 Prometheus 推算，并标明“推算”。

集群名是系统参数 cluster.name（默认 default），出现在节点与工作负载的数据、资源页面、邮件和 Grafana 看板的集群变量里。平台管理一个集群：生产里请把它改成有意义的名字，例如 prod-east。

Grafana 看板

仓库的 deploy/grafana 提供资源看板，系统设置里可以填写 Grafana 的地址，资源大盘各处的“在 Grafana 打开”链接按模块与窗口带上变量。

使用边界

  • Operator 只用模拟客户端测试过，没有在真实集群验证。
  • 读取是只读的，上报不改变集群；副本由 Operator 在 Auto 模式下另行执行，见准入与伸缩。
