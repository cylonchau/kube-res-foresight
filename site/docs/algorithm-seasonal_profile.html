使用指南

Seasonal Profile · 周期画像

← 算法与模型总览

用途与适用负载

按一天中的时段和周几分桶，对每个桶取衰减百分位。适合“工作日上午忙、周末安静”等有时钟规律的负载。

历史数据与运行条件

运行最低 4 点；周几画像需要足够周历史与桶样本。不够时依次退到每日同一时刻、整段历史百分位。

输入应是等间隔、无缺口且数值有限的序列。输出保留输入指标单位，例如 CPU 核、内存字节或每秒请求数；采样步长决定步数对应的真实时间。最低样本数仅表示可运行，不代表预测可靠。

此方法不使用协变量；分别预测各目标指标。

原理与公式

季节画像把历史按“一周中的哪一天 + 一天中的哪个时段”分桶，每个桶里放过去所有同一时刻的样本。预测某个未来时刻，就是读这个时刻所在桶的带衰减的分位数。这是 VPA/Autopilot 的“分位数推荐器”加上了钟表。

公式
桶：    本地时间 = UTC + utc_offset_minutes
        桶号   = ⌊(本地时间的“当天分钟数”) / bucket_minutes⌋
        开启 by_weekday 时桶 = (星期几, 桶号)，共 7 × (1440/bucket_minutes) 个桶；否则只按桶号分，共 1440/bucket_minutes 个

权重：  w(i) = 0.5 ^ (age(i) / H)，H = half_life_days 换算成步数（0 = 不衰减）

读取（按顺序，用第一个够用的）：
  1) 开启 by_weekday 且“星期+时段”桶里至少有 min_samples_per_bucket 个样本 → 该桶的加权分位数
  2) 否则，“时段”桶（所有星期合并）里样本够 → 该桶的加权分位数
  3) 否则 → 整个历史的加权分位数（这时它和 hist_percentile 一样）

加权分位数：按值排序、累加权重，取累计权重第一次 ≥ (percentile/100) × 总权重 的值
预测：  ŷ = 分位值 × (1 + safety_margin)

参数怎样进入公式：

  • percentile：桶里取第几百分位，越高越保守（默认 90）。
  • bucket_minutes：桶的宽度（分钟），必须能整除 1440。60 表示一小时一个桶。
  • by_weekday：是否区分星期几（默认是）。不区分时，所有星期合并成一天的形状。
  • half_life_days：样本权重的半衰期（天，默认 14）。让近期比远期更有影响力。
  • min_samples_per_bucket：桶里至少要有多少个样本才信任（默认 6）；不够就退到上面的下一级。注意它数的是样本数，不是周期数：步长很细时，一天里一个桶就有好几个样本。
  • utc_offset_minutes：时区，北京时间 = 480（默认）。决定“早 9 点”是哪个桶。
  • safety_margin：在分位值上再加的余量。

为什么这样做：“每天早上 9 点必高峰”这种负载，一个与时间无关的平线（hist_percentile）要么在平时浪费，要么在高峰不够。分桶后每个时段有自己的水平：9 点读 9 点的桶，凌晨读凌晨的桶。用分位数而不是平均，是为了盖住该时段通常的峰值，这是资源推荐想要的；与“季节持续”相比，每一天都是一票，某一天的异常只是众多票里的一票。

注意：分位数是“偏保守”的，不是“预期负载”，需求拆解里会标出。样本少时（比如只有 3 天），90 分位几乎等于最大值。平台另有规则：历史里要有足够多个完整周期（系统参数 forecast.min_seasons，默认 3）它才可以参与决策，因为一天的形状只由一天学来，这一天的异常也会被当作模式。

参数说明

窄屏可左右滑动参数表，查看完整说明。

参数 / 类型默认值 / 范围 / 单位含义与使用
percentile
float		90
≥ 1; ≤ 100		取第几百分位，如 90、95；越大越保守。
bucket_minutes
int		60
≥ 1; ≤ 720; minutes		时间桶的长度（分钟），必须能整除一天（1440）：60 = 每小时一个桶，15 = 每 15 分钟一个桶。
by_weekday
bool		true
无额外范围限制		是否区分周几：true = 周一九点和周六九点是两个桶（至少需要两周历史才有各自的数据，不够时退到每天同一时刻）；false = 只看一天中的时刻。
half_life_days
float		14
≥ 0; ≤ 365; days		半衰期：这么多天之前的样本只算一半权重；0 表示不衰减。
min_samples_per_bucket
int		6
≥ 1; ≤ 100000		一个桶至少有多少个样本才被信任；不够就退到上一级（每天同一时刻，再退到整段历史）。
utc_offset_minutes
int		480
≥ -720; ≤ 840; minutes		时区偏移（相对 UTC，分钟），决定「几点」「周几」按哪个时区的钟面分桶。默认 480（UTC+8，平台的时区）：这样「九点」是北京时间九点，周一从北京时间零点开始；部署在别的时区就改成那里的偏移。
safety_margin
float		0
≥ 0; ≤ 5		安全边际：结果再乘 (1+边际)。

配置示例

在“算法管理”编辑参数。以下仅为参数对象，不是 config.yaml 全文；周期示例按 5 分钟采样，需按实际步长调整。未列出的可选参数使用上表默认值。

JSON
{
  "percentile": 90,
  "bucket_minutes": 60,
  "by_weekday": true,
  "half_life_days": 14,
  "utc_offset_minutes": 480
}

计算示例：数据、参数与代入过程

为了看清，用一个粗的设定：每 6 小时一个点，桶宽 360 分钟（一天 4 个桶），不区分星期，不衰减，每桶至少 2 个样本，时区用 UTC。历史是 3 天的 CPU 使用量（核）。

JSON
{
  "percentile": 90,
  "bucket_minutes": 360,
  "by_weekday": false,
  "half_life_days": 0,
  "min_samples_per_bucket": 2,
  "utc_offset_minutes": 0
}

第 2 步，读每个桶的 90 分位。不衰减，3 个样本权重相同，目标累计权重 = 0.9 × 3 = 2.7。排序后累计权重是 1、2、3，第一次 ≥ 2.7 的是第 3 个，也就是最大值：

第 3 步，预测接下来 4 步（周六 00:00、06:00、12:00、18:00），每一步读它所在的桶，safety_margin 为 0：

结果
ŷ = [22, 38, 70, 32]

这个例子说明了两点：一是 90 分位在样本很少时就是最大值（12:00 的 70 来自第 3 天的那一次峰值）；二是每个时段各读各的桶，预测形状和历史的日内形状一致。样本再多一些，高分位数才会更稳。

这些数字由 pkg/forecast/docs_examples_test.go 用真实代码算出并持续校验。

调参与取舍

bucket_minutes 必须整除 1440。更小的桶需要更多历史。utc_offset_minutes=480 按 UTC+8 分桶，是固定偏移，不会自动处理夏令时。

来源与引用

  • Kubernetes Vertical Pod Autoscaler（VPA）的推荐器：用带衰减的直方图取目标分位数。kubernetes/autoscaler 的 vertical-pod-autoscaler 目录。
  • Rzadca, K. 等 “Autopilot: Workload Autoscaling at Google”，EuroSys 2020：Google 的 Autopilot，同样使用带衰减的分位数推荐，并比较了多种推荐器。
  • “加上钟表”（按星期和时段分桶）是本平台在上述推荐器上的扩展，不是 VPA 或 Autopilot 论文里的原有做法；它与 hist_percentile 的关系是：桶不够用时退化成它。

通用参数：变化重置与分位校准

参数 / 类型默认值 / 范围 / 单位含义与使用
reset_on_change
bool		false
无额外范围限制		水平突变后重置：检测历史里最后一次水平突变（发布、扩缩容、流量切换），只用突变之后的历史预测。关闭时用全部历史（现状）。突变之后至少要有 6 步才会被确认；突变后的历史不够算法所需时，取算法所需的最新一段。
change_threshold
float		8
≥ 3; ≤ 50		突变阈值：突变幅度（扣除前一段趋势后）超过噪声的多少倍才算，越大越不容易误报，噪声由相邻步变化的稳健标准差估计。仅 reset_on_change=true 时使用。
change_min_shift
float		0.2
≥ 0; ≤ 5		最小突变幅度：突变至少是水平的这个比例（0.2 = 20%），很干净的序列上的微小跳变不算。仅 reset_on_change=true 时使用。
quantile_level
float		0
≥ 0; ≤ 0.99		推荐分位数：0 = 点预测（现状）；0.9 等 = 预测「实际值有约 90% 的把握不超过」的线（保形预测：用本算法在这个负载最近几个窗口里的真实误差校准，需要更多历史和时间）。必须大于 0.5。
calibration_windows
int		8
≥ 3; ≤ 50		校准窗口数：用最近多少个历史窗口测本算法的误差；越多越稳，也越慢（每个窗口多跑一次预测）。仅推荐分位数大于 0 时使用。

quantile_level 是 0～1 的分位点，percentile 是 1～100 的百分数，二者不是同一参数。分位校准会额外运行历史预测；增加校准窗口前检查历史与运行预算，覆盖率是评估目标而非保证。

在模块中使用

  1. 保存参数，检查历史窗口、采样步长和预测范围。
  2. 打开模块的“启用预测”；固定算法只运行指定方法，动态算法使用平台已启用的方法。
  3. 先运行滚动回测，通过版本晋升后才会采用；修改影响模型版本的参数后重新回测。
  4. 在仅观察或仅推荐下检查误差、峰值低估、耗时与采用原因，再分别授权准入和副本执行。

历史不足、参数不合法、运行超时或输出无效时，检查算法运行原因；没有合格预测时按模块的固定周期、兜底与保护规则处理。
