使用指南

MSTL · 多重季节分解

同时分离日、周季节形状，对去季节后的序列使用 Theta。本项目采用固定季节形状的迭代分解，不是随时间变化的 LOESS 分解。

← 算法与模型总览

用途与适用负载

同时分离日、周季节形状，对去季节后的序列使用 Theta。本项目采用固定季节形状的迭代分解，不是随时间变化的 LOESS 分解。

历史数据与运行条件

至少最长周期的两倍。5 分钟采样的日周期需要 576 点；加周周期后需要 4032 点，即两周。

输入应是等间隔、无缺口且数值有限的序列。输出保留输入指标单位，例如 CPU 核、内存字节或每秒请求数；采样步长决定步数对应的真实时间。最低样本数仅表示可运行，不代表预测可靠。

此方法不使用协变量；分别预测各目标指标。

原理与公式

MSTL（多重季节-趋势分解）用于同时有“日周期”和“周周期”的负载。它把序列拆成趋势和每个周期各自的季节形状，把季节形状拿走，对剩下的（趋势加噪声）用 Theta 预测，再把季节形状加回去。

公式
分解：  y(t) = trend(t) + S_day(t mod 日周期) + S_week(t mod 周周期) + remainder(t)
预测：  ŷ(T+h) = Theta( y − S_day − S_week )(h) + S_day((T+h) mod 日周期) + S_week((T+h) mod 周周期)
        小于 0 的预测截为 0

每个季节形状 S 的估计（重复 3 遍，使各个形状互相一致）：
  r(t)  = y(t) − trend(t) − 其他周期的形状
  S(pos) = 位置 pos 上所有周期的 r 的平均，再整体减去均值（使形状的平均为 0）
  trend  = 把去掉季节后的序列做一次以“最长周期”为窗口的居中移动平均

参数怎样进入公式：

  • daily_season_steps：一天有多少步（较短的周期）。5 分钟一个点 = 288。
  • weekly_season_steps：一周有多少步，必须比日周期长；5 分钟一个点 = 2016。填 0 表示只有日周期。
  • 最少样本数 = 2 × 最长周期（至少看到两整个周期，否则一个位置只见过一次，分不清是季节还是噪声）。

为什么这样做：真实的业务负载常常“工作日白天高、夜里低，周末又整体偏低”，一个周期的季节算法只能抓到一种。把两种周期分开估计、再加回来，就能同时表达“每天几点高”和“每周哪几天高”。

与论文的差别：论文里的 STL 用 LOESS 平滑每个季节形状，所以形状可以慢慢变化；这里每个季节形状是固定的，等于历史上所有周期在该位置的平均（先扣掉趋势和其他周期）。好处是便宜且不需要调参，代价是形状在历史里发生变化时只会被平均，不会被跟随。

参数说明

窄屏可左右滑动参数表，查看完整说明。

参数 / 类型默认值 / 范围 / 单位含义与使用
daily_season_steps
int		必填，无默认值
≥ 2; steps		一天的步数 = 86400 / 步长秒数（1 分钟一步是 1440，5 分钟一步是 288）。
weekly_season_steps
int		0
≥ 0; steps		一周的步数 = 7 × 一天的步数；0 = 只做日季节。必须大于一天的步数。启用周季节至少需要两周历史。

配置示例

在“算法管理”编辑参数。以下仅为参数对象，不是 config.yaml 全文；周期示例按 5 分钟采样，需按实际步长调整。未列出的可选参数使用上表默认值。

JSON
{
  "daily_season_steps": 288,
  "weekly_season_steps": 2016
}

计算示例：数据、参数与代入过程

为了看清，用一个只有 4 步的“迷你日周期”，没有周周期，一共 3 个周期（12 个点）。数据是人为构造的：基线 10，每步上升 0.5，再叠加季节形状 [−2, 0, +3, −1]。

JSON
{
  "daily_season_steps": 4,
  "weekly_season_steps": 0
}
数据
y = [8, 10.5, 14, 10.5,   10, 12.5, 16, 12.5,   12, 14.5, 18, 14.5]
    └─ 第 1 个周期 ─┘      └─ 第 2 个周期 ─┘      └─ 第 3 个周期 ─┘

第 1 步，估计季节形状。算法扣掉趋势后，对同一位置的 3 个值取平均并让整体均值为 0，重复 3 遍。得到的形状是

结果
S_day = [−2.1913, −0.0491, +3.0693, −0.8289]        （平均为 0）

很接近我们构造时用的 [−2, 0, +3, −1]，偏差来自上升趋势和居中移动平均在序列两端的边界效应。

第 2 步，对去掉季节后的序列做 Theta 预测（序列大致是一条每步升 0.5 的直线）。以第 1 步为例，基础预测是 13.3812 − (−2.1913) = 15.5725。

第 3 步，加回季节形状。下一步对应的位置是 12 mod 4 = 0，所以：

计算
ŷ(T+1) = 基础预测 + S_day[0] = 15.5725 + (−2.1913) = 13.3812
ŷ(T+2) = …                    + S_day[1]                     = 15.7672
ŷ(T+3) = …                    + S_day[2]                     = 19.1292
ŷ(T+4) = …                    + S_day[3]                     = 15.4747

结果 [13.3812, 15.7672, 19.1292, 15.4747]：一个“上升后的波形”，四个点的高低次序和季节形状一致。

顺便看一个局限：构造数据时的“真值”（基线继续每步升 0.5）应当是 [14, 16.5, 20, 16.5]，而预测略低（偏低约 0.6 到 1.0），因为 Theta 只取趋势的一半。这是用 Theta 做基础预测的特性：对稳定上升的负载偏保守地低。

这些数字由 pkg/forecast/docs_examples_test.go 用真实代码算出并持续校验。

调参与取舍

先配置 daily_season_steps。weekly_season_steps=0 只做日季节；启用周季节时必须大于日周期，历史不足会跳过而非补齐。

来源与引用

  • Cleveland, R.B.、Cleveland, W.S.、McRae, J.E.、Terpenning, I. “STL: A seasonal-trend decomposition procedure based on Loess”，Journal of Official Statistics 6(1)，1990，3–73：单季节的 STL，MSTL 的基础。
  • Theta 作为底层预测：见本站的 Theta 页。
  • 与论文的差别见上文“与论文的差别”：本实现的季节形状固定（所有周期的平均），不用 LOESS。

通用参数：变化重置与分位校准

参数 / 类型默认值 / 范围 / 单位含义与使用
reset_on_change
bool		false
无额外范围限制		水平突变后重置：检测历史里最后一次水平突变（发布、扩缩容、流量切换），只用突变之后的历史预测。关闭时用全部历史（现状）。突变之后至少要有 6 步才会被确认；突变后的历史不够算法所需时，取算法所需的最新一段。
change_threshold
float		8
≥ 3; ≤ 50		突变阈值：突变幅度（扣除前一段趋势后）超过噪声的多少倍才算，越大越不容易误报，噪声由相邻步变化的稳健标准差估计。仅 reset_on_change=true 时使用。
change_min_shift
float		0.2
≥ 0; ≤ 5		最小突变幅度：突变至少是水平的这个比例（0.2 = 20%），很干净的序列上的微小跳变不算。仅 reset_on_change=true 时使用。
quantile_level
float		0
≥ 0; ≤ 0.99		推荐分位数：0 = 点预测（现状）；0.9 等 = 预测「实际值有约 90% 的把握不超过」的线（保形预测：用本算法在这个负载最近几个窗口里的真实误差校准，需要更多历史和时间）。必须大于 0.5。
calibration_windows
int		8
≥ 3; ≤ 50		校准窗口数：用最近多少个历史窗口测本算法的误差；越多越稳，也越慢（每个窗口多跑一次预测）。仅推荐分位数大于 0 时使用。

quantile_level 是 0～1 的分位点，percentile 是 1～100 的百分数，二者不是同一参数。分位校准会额外运行历史预测；增加校准窗口前检查历史与运行预算，覆盖率是评估目标而非保证。

在模块中使用

  1. 保存参数，检查历史窗口、采样步长和预测范围。
  2. 打开模块的“启用预测”；固定算法只运行指定方法，动态算法使用平台已启用的方法。
  3. 先运行滚动回测，通过版本晋升后才会采用；修改影响模型版本的参数后重新回测。
  4. 在仅观察或仅推荐下检查误差、峰值低估、耗时与采用原因，再分别授权准入和副本执行。

历史不足、参数不合法、运行超时或输出无效时，检查算法运行原因；没有合格预测时按模块的固定周期、兜底与保护规则处理。
