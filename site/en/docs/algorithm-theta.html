USER GUIDE

Theta

Combines a smoothed level with half the fitted linear slope, optionally removing seasonality first. A candidate for noisy trends; forecasts are clamped at zero.

← Models and prediction modes

Purpose and workload fit

Combines a smoothed level with half the fitted linear slope, optionally removing seasonality first. A candidate for noisy trends; forecasts are clamped at zero.

History and runtime requirements

Four observations without seasonality, or two full cycles with it.

Inputs must be regularly sampled, gap-free, and finite. Outputs retain the metric unit, such as CPU cores, memory bytes, or requests per second. The sample interval determines the duration of a step. Minimum history permits execution; it does not establish forecast quality.

This method does not use covariates; target metrics are forecast separately.

How it works and the formula

The Theta method won the M3 forecasting competition. Its simple form (Hyndman and Billah) amounts to this: smooth the series with simple exponential smoothing to get a "level", then add a "drift" equal to half the slope of the linear trend. The level follows the recent past and the trend is trusted by half, which is why it is hard to beat on short, noisy series.

Formula
x = the seasonally adjusted series (the series itself without a season)
ℓ  = the last level of simple exponential smoothing of x (coefficient α)
b  = the least-squares slope of x over time (per step)
n  = the length of the series

ŷ(T+h) = ℓ + (b/2) · ( (h−1) + 1/α − (1−α)ⁿ / α )        h = 1 … H
finally the season term is put back and a forecast below 0 is cut to 0

In the bracket (h−1) means the drift runs one more step for every step ahead; 1/α − (1−α)ⁿ/α is a fixed offset between the smoothed level and the trend line.

How the parameters enter the formula:

  • alpha: the smoothing coefficient of the level. 0 means choose automatically: 0.05, 0.10 … 1.00 are tried and the α with the smallest in-sample one-step squared error wins.
  • season_length_steps (m): the season length in steps. 0 or 1 means no season; with a season at least 2m points are needed. With a season the classical decomposition (a centred moving average) first gives a seasonal index for every position: multiplicative (the series divided by the index) when the history is all positive, additive (the index subtracted) otherwise; the index is put back after the forecast.

Why it is done this way: looking at the level alone lags a rising trend, extrapolating the whole trend tends to overshoot. Taking half the slope is the compromise: it follows a slow change without being led astray by a few points. No training and few parameters to tune.

Configuration example

Edit parameters in Algorithm management. This is a parameter object, not a complete config.yaml. Seasonal examples assume five-minute sampling; adjust for your actual interval. Omitted optional values use the defaults above.

JSON
{
  "season_length_steps": 288,
  "alpha": 0
}

Worked example: data, parameters and substitution

No season, α set by hand (so there is no automatic choice). One point every 5 minutes.

JSON
{
  "alpha": 0.5
}
Data
y = [10, 12, 11, 13, 14, 16]        n = 6

Step 1, the level ℓ by simple exponential smoothing (ℓ(1) = 10, then ℓ ← 0.5·y + 0.5·ℓ): 10 → 11 → 11 → 12 → 13 → 14.5.

Step 2, the least-squares slope b: a line through (0,10), (1,12), (2,11), (3,13), (4,14), (5,16) has the slope 1.0857 per step.

Step 3, substitute. (1−α)ⁿ = 0.5⁶ = 0.015625, so 1/α − (1−α)ⁿ/α = 2 − 0.03125 = 1.96875, and b/2 = 0.54285:

Calculation
ŷ(T+1) = 14.5 + 0.54285 × ( 0 + 1.96875) = 15.5687
ŷ(T+2) = 14.5 + 0.54285 × ( 1 + 1.96875) = 16.1116
ŷ(T+3) = 14.5 + 0.54285 × ( 2 + 1.96875) = 16.6545

The result is [15.5687, 16.1116, 16.6545]. For comparison, extrapolating the whole trend (the slope 1.0857 instead of half) would add 1.09 per step; Theta adds only 0.54, which is "the trend trusted by half".

These numbers are computed by the real code in pkg/forecast/docs_examples_test.go and checked on every test run.

Tuning and tradeoffs

alpha=0 selects smoothing automatically. Compare the nonseasonal form first; add a season only when it is clear and sufficient history exists.

Sources and references

  • Assimakopoulos, V. & Nikolopoulos, K. "The theta model: a decomposition approach to forecasting", International Journal of Forecasting 16(4), 2000, 521–530: the original paper.
  • Hyndman, R.J. & Billah, B. "Unmasking the Theta method", International Journal of Forecasting 19(2), 2003, 287–290: shows it equals simple exponential smoothing with drift (the form implemented here).
  • Makridakis, S. & Hibon, M. "The M3-Competition: results, conclusions and implications", International Journal of Forecasting 16(4), 2000, 451–476: where Theta won.
  • Classical seasonal decomposition (seasonal indices from a centred moving average) is described in Hyndman & Athanasopoulos, Forecasting: Principles and Practice (3rd ed.), section 3.4: https://otexts.com/fpp3/classical-decomposition.html.

Shared parameters: shifts and quantiles

Parameter / typeDefault / range / unitMeaning and use
reset_on_change
bool		false
No additional range		Use history after a detected level shift, preserving enough points for the underlying method.
change_threshold
float		8
≥ 3; ≤ 50		Minimum shift relative to robust noise; used only with reset_on_change.
change_min_shift
float		0.2
≥ 0; ≤ 5		Minimum relative level shift; 0.2 means 20%. Used only with reset_on_change.
quantile_level
float		0
≥ 0; ≤ 0.99		Zero disables conformal calibration; otherwise must be above 0.5 and at most 0.99. Calibrates an upper forecast using earlier forecast errors.
calibration_windows
int		8
≥ 3; ≤ 50		Historical windows for conformal calibration; more windows add forecast calls and history requirements.

quantile_level uses a 0–1 scale; percentile uses 1–100. Calibration runs extra historical forecasts. Check history and runtime budgets before increasing windows; coverage is an evaluation target, not a guarantee.

Use in a module

  1. Save parameters and check history, sample interval, and horizon.
  2. Enable module prediction. Fixed mode runs the selected method; dynamic mode uses centrally enabled methods.
  3. Run rolling backtests and earn version promotion before adoption. Re-run backtests after changes affecting model identity.
  4. Review error, peak underestimation, runtime, and adoption reasons in Observe or Recommend before separately authorizing admission and replica actions.

For insufficient history, invalid settings, timeouts, or invalid output, inspect run reasons. Without eligible forecasts, the module follows its schedules, fallback, and protection rules.
