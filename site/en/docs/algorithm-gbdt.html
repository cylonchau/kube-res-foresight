USER GUIDE

GBDT

Fits successive trees to residuals using lags, calendars, and covariates. Supports squared-error point forecasts or a native quantile objective.

← Models and prediction modes

Purpose and workload fit

Fits successive trees to residuals using lags, calendars, and covariates. Supports squared-error point forecasts or a native quantile objective.

History and runtime requirements

At least lags + 4×min_samples_leaf + 1 observations; direct mode adds horizon−1.

Inputs must be regularly sampled, gap-free, and finite. Outputs retain the metric unit, such as CPU cores, memory bytes, or requests per second. The sample interval determines the duration of a step. Minimum history permits execution; it does not establish forecast quality.

Supports covariates on the same sample grid, using only observations before the forecast origin. Future covariates carry the last observed value; future business demand is not assumed known.

How it works and the formula

GBDT (gradient-boosted regression trees) adds trees one after another: start from a constant, and with every new tree fit "how far the current forecast is off" (the residual), then add that tree to the total forecast by a small share, the learning rate. The features are the previous values, optional calendar features and covariates; the forecast rolls forward recursively (or one ensemble is trained per anchor step).

Formula
start:    F₀ = the mean of the training targets (the alpha-quantile when objective = quantile)
tree m (m = 1 … M, M = n_estimators):
  residual   r(i) = y(i) − F(m−1)(x(i))                     (with the quantile objective the "gradient" fitted is alpha or alpha−1 and a leaf takes the alpha-quantile of the residuals)
  split      bin each feature into 32 bins and pick the (feature, bin edge) of the largest gain:
               gain = (ΣL)²/nL + (ΣR)²/nR − (Σ)²/n           Σ is the sum of the residuals on that side, n the number of rows
             recurse to depth max_depth, or until a side has fewer than min_samples_leaf rows; a leaf's value = the mean of its residuals
  update     F(m)(x) = F(m−1)(x) + learning_rate × tree_m(x)
forecast:  ŷ(t) = F(M)( x(t) ), several steps recursively: the forecast is used as the lag of the next step

How the parameters enter the formula:

  • lags: how many previous steps are features, required; calendar_features, covariate_lags, training_window_steps as in ridge autoregression.
  • n_estimators (M): the number of trees (default 100).
  • learning_rate: the share each tree contributes (default 0.1). Smaller needs more trees and overfits less easily.
  • max_depth, min_samples_leaf: as in the random forest. The least history = lags + 4×min_samples_leaf + 1.
  • objective: squared is a squared-error point forecast; quantile forecasts the alpha quantile with the pinball loss (0.9 = the actual stays below it about 90% of the time), for peak or capacity protection; its coverage has to be verified separately.
  • multi_step, direct_anchors: recursive or direct several steps, as in ridge autoregression.

Why it is done this way: every tree is shallow and weak by itself; fitting the residuals one after another brings the total forecast closer to the target step by step. That expresses non-linear relations and overfits less easily than one deep tree. The quantile objective lets it forecast a deliberately high line directly, which suits capacity protection.

Limit: like every tree model GBDT cannot extrapolate: a forecast stays inside the range of the training targets (see the example of the random forest page). The trees here are deterministic, with no sampling, so the same history always gives the same forecast.

Configuration example

Edit parameters in Algorithm management. This is a parameter object, not a complete config.yaml. Seasonal examples assume five-minute sampling; adjust for your actual interval. Omitted optional values use the defaults above.

JSON
{
  "lags": 24,
  "n_estimators": 100,
  "learning_rate": 0.1,
  "max_depth": 3,
  "training_window_steps": 5000,
  "multi_step": "recursive",
  "objective": "squared"
}

Worked example: data, parameters and substitution

To list every step we use the smallest setting: 2 lags, 1 tree of depth 1 (a single split), learning rate 0.5.

JSON
{
  "lags": 2,
  "n_estimators": 1,
  "learning_rate": 0.5,
  "max_depth": 1,
  "min_samples_leaf": 1,
  "objective": "squared"
}
Data
y = [10, 12, 13, 15, 14, 16, 18, 17, 19, 21]        one point every 5 minutes, forecast 2 steps

Step 1, the training rows and the start. 8 rows; the mean of the targets F₀ = (13+15+14+16+18+17+19+21)/8 = 16.625. The residual of each row is r = y − 16.625:

feature y(t−1)feature y(t−2)target y(t)residual r
121013−3.625
131215−1.625
151314−2.625
141516−0.625
161418+1.375
181617+0.375
171819+2.375
191721+4.375

Step 2, find the best single split. Among all (feature, threshold) pairs take the largest gain. The best is "y(t−1) ≤ 15":

Calculation
left  (y(t−1) ≤ 15: the four rows 12, 13, 15, 14):  sum of residuals = −3.625 −1.625 −2.625 −0.625 = −8.5,  nL = 4
right (y(t−1) > 15: the four rows 16, 18, 17, 19): sum of residuals = +1.375 +0.375 +2.375 +4.375 = +8.5,  nR = 4
total = 0, n = 8
gain = 8.5²/4 + 8.5²/4 − 0²/8 = 18.0625 + 18.0625 = 36.125

A leaf's value is the mean of its residuals: left = −8.5/4 = −2.125, right = +8.5/4 = +2.125.

Step 3, forecast. The next point has the last two values as features: y(t−1) = 21, y(t−2) = 19. 21 > 15, so it goes to the right leaf, which contributes +2.125, times the learning rate 0.5:

Calculation
ŷ(T+1) = F₀ + 0.5 × 2.125 = 16.625 + 1.0625 = 17.6875

Step 4, recursion. The features of step 2 are y(t−1) = 17.6875 (also > 15), so it goes to the right leaf again and ŷ(T+2) = 17.6875. The forecast is [17.6875, 17.6875].

Two things to note: the last value of the history is 21 and the forecast is 17.69, much lower than the latest value: with one shallow tree it is closer to "the overall mean plus a small adjustment"; and a learning rate of 0.5 lets each tree contribute only half. Set n_estimators to 2 and the second tree fits the residuals left by the first, so the step-1 forecast becomes 18.84375; the more trees, the closer the forecast gets to the detail of the training data, and the more easily it overfits. The real defaults are 100 trees, depth 3 and learning rate 0.1.

These numbers are computed by the real code in pkg/forecast/docs_examples_test.go and checked on every test run.

Tuning and tradeoffs

Smaller learning_rate generally needs more trees. alpha denotes a quantile only when objective=quantile, unlike EWMA alpha. Compare native quantiles and conformal calibration separately before stacking upward adjustments.

Sources and references

  • Friedman, J.H. "Greedy function approximation: a gradient boosting machine", The Annals of Statistics 29(5), 2001, 1189–1232: the original paper of gradient boosting.
  • Koenker, R. & Bassett, G. "Regression quantiles", Econometrica 46(1), 1978, 33–50: quantile regression and the pinball loss.
  • Ke, G. et al. "LightGBM: A Highly Efficient Gradient Boosting Decision Tree", NeurIPS 2017: binning feature values (a histogram) to speed up splitting; this implementation uses 32 bins, a simplified version that does not depend on that library.
  • Breiman et al. Classification and Regression Trees (1984): regression trees and the variance-reduction split criterion, as on the random forest page.

Use in a module

  1. Save parameters and check history, sample interval, and horizon.
  2. Enable module prediction. Fixed mode runs the selected method; dynamic mode uses centrally enabled methods.
  3. Run rolling backtests and earn version promotion before adoption. Re-run backtests after changes affecting model identity.
  4. Review error, peak underestimation, runtime, and adoption reasons in Observe or Recommend before separately authorizing admission and replica actions.

For insufficient history, invalid settings, timeouts, or invalid output, inspect run reasons. Without eligible forecasts, the module follows its schedules, fallback, and protection rules.
