# 算法质量改进：评审结论、选型取舍与工作包（2026-10-28）

依据：对 `pkg/forecast`、`pkg/backtest`、`forecastsvc/backtest.go` 的代码评审（GBDT、神经网络、朴素贝叶斯、公式算法只看了注释与参数，未细读），以及公开竞赛与系统文献的结论。**没有在本项目数据上测过准确率**；下面的“业界依据”不是本项目的验收结论，本项目的结论只来自自己的滚动回测（见 A0）。

## 1. 评审发现（按影响排序）

| # | 问题 | 位置 | 影响 |
|---|---|---|---|
| F1 | 多步预测递归：预测值回灌为下一步输入（岭回归、随机森林、GBDT、神经网络、朴素贝叶斯） | ridge.go、forest.go 等 | 预测视野越长越向均值收敛，峰值偏低；树模型不能外推 |
| F2 | 评分以 WAPE 为主，对高估与低估同权 | backtest.go、评分 | 扩缩容里低估代价更大，排名与风险不一致 |
| F3 | 回测默认 5 个起点，总点数约 5×horizon | backtest.go Config | 排名、晋升对少数窗口敏感，可能只覆盖一天中的几个时段 |
| F4 | 起点按各模型自己的 `MinSamples` 截断，晋升比较（`Evaluate`）并非总在同一批起点 | backtest.go:61-74 | 历史较短时，需要整天历史的 `seasonal_naive` 与候选比较的是不同时间窗 |
| F5 | KNN 候选窗口逐步滑动，最近邻常为相邻窗口，无互斥区、无时刻约束 | knn.go:68 | 同一事件被重复计数，实际接近 K=1 |
| F6 | 日历特征只有一阶正弦/余弦 | features.go:54 | 尖锐日高峰需靠 lag 拟合，lag 覆盖不到前一天时拟合不出 |
| F7 | Holt-Winters 只有加性季节，输出不截断为非负，初始趋势只用前 4 点 | holtwinters.go | 峰值随水平放大的负载误差系统性偏差；可能出现负预测 |
| F8 | MACD 斜率为近似公式，信号线不确认时减半是经验值 | macd.go | 只做有上限修正，风险受控；收益无证据 |
| F9 | hist_percentile 是平线，无时间维度 | percentile.go | 作为保守基线合理，对强日周期负载长期偏高/偏低 |

已核对无问题：回测无泄漏（模型只拿 `Values[:c]`，协变量同样截断）；NaN/Inf 拒绝；历史不足跳过不补数；随机森林、神经网络固定种子可复现。

## 2. 选型取舍

**保留为主力**：季节性朴素 + 衰减百分位基线（VPA、Google Autopilot 在线上使用）；ETS/Holt-Winters 与 Theta（M3/M4 竞赛里短历史单序列的强基线）；GBDT（M5 竞赛前列几乎都是 LightGBM，但那是数万序列的全局模型）。

**新增**：Theta；乘性季节 Holt-Winters 与非负截断；保形（conformal）分位数包装器，让推荐用 P90 之类分位数而不是点预测的峰值；MSTL（日+周双季节）；全局模型（同类工作负载合训，先做设计）。

**不作主力、不投入**：LSTM/GRU/Transformer（已有 GRU/LSTM，保留为候选；单工作负载几千点上公开对比常不如 ETS/线性）；Prophet（无成熟纯 Go 实现，公开对比常不如 ETS/Theta）；N-BEATS/N-HiTS/TFT（需要 GPU 或大量训练，与“纯 Go 进程内”约束冲突）。

## 2.1 主力算法清单：现状、缺口与对应工作包

“保留为主力”的四类算法各自对照代码现状，缺口全部落到工作包，不留在文字里。现状栏来自对 `pkg/forecast` 的阅读（2026-10-28），不是实测结论。

| 主力算法 | 为什么 | 业界依据 | 代码现状 | 缺口 | 工作包 |
|---|---|---|---|---|---|
| 季节性朴素 + 历史分位数（VPA/Autopilot 式） | 简单、几乎不会出大错，是必须打赢的基线 | Kubernetes VPA 的推荐器和 Google Autopilot（EuroSys 2020）都用带时间衰减的分位数，线上长期使用 | `seasonal_naive`、`hist_percentile`（百分位、半衰期、安全余量）已实现；晋升时的隐式基线是 naive 和“昨天同一时刻” | 基线只在各自可用的起点上被比较（F4）；`hist_percentile` 是平线，没有时间维度（F9）；基线是否稳定打赢没有实测 | A0 实测其表现；A1 让基线与候选同起点；是否把按时刻分桶的百分位作为新基线，等 A0 结果再定 |
| ETS / Holt-Winters（含乘性季节、阻尼趋势） | 单序列、短历史下稳，速度快，可解释 | M3、M4 竞赛里 ETS、Theta 类方法长期是很难打败的基线，M4 里大多数纯机器学习方法没有超过它们的组合 | `holt_winters` 已有加性季节、可选趋势与阻尼（φ=0.98 固定）；参数在小网格里按样本内误差选 | 无乘性季节；输出不截断为非负；非季节趋势初值只用前 4 点（F7）；阻尼系数不可调 | A4 |
| Theta | 实现很小，在竞赛里常常胜过复杂模型 | M3 冠军方法，M4 里表现稳 | 未实现 | 整个算法缺失 | A4 |
| GBDT（LightGBM 类），直接多步，分位数损失 | 能吃日历和协变量（比如请求量），速度可接受 | M5 竞赛前列几乎都是 LightGBM，但那是数万条序列的全局模型 | `gbdt` 已有分位数损失（`Quantile`、`Alpha`）、日历与协变量特征；多步是递归的（F1） | 无直接多步；单工作负载训练，没有 M5 那种跨序列合训的收益；分位数模式的低估指标没有进入排名（F2） | A5 直接多步；A2 低估指标进排名；A8 全局模型设计 |

说明：M5 的结论来自数万条序列合训，单工作负载 GBDT 不一定复现；这是把全局模型（A8）放进计划的原因，也是 GBDT 在 A0 之前不能默认“更好”的原因。

## 3. 工作包

顺序按依赖：先测基线与修评估，否则新算法无法可信比较。

| 包 | 内容 | 验收 |
|---|---|---|
| A0 基线测量 | 用测试平台真实历史把现有算法全跑一遍滚动回测，记录每个算法的点数、起点数、WAPE、峰值低估、覆盖率、耗时，存入进度文档 | 报告可复现（命令 + 数据范围）；明确这是测试环境数据，不是生产结论 |
| A1 回测公平 | 候选与基线只在共同起点上比较；起点数可配并默认提高；起点按时段错开，覆盖不同时刻；评分页展示点数/起点数 | 单测：短历史下候选与基线用同一批起点；结果里能看到共同起点数 |
| A2 低估敏感评分 | 增加“低估惩罚”指标（高分位 pinball 或低估成本）并参与排名与晋升；WAPE 保留作准确度 | 单测：对偏低预测与偏高预测的同等误差得分不同；晋升规则文档化 |
| A3 保形分位数 | 在任意算法外包一层：用滚动回测残差按预测步分别估计分位，输出 P50/P90；模块增加“推荐分位数”参数，决策用它求峰值 | 单测：覆盖率在合成数据上接近名义水平；回测无泄漏；兼容旧模块（默认等同现状） |
| A4 Holt-Winters 补强 + Theta | 乘性季节选项、非负截断、更稳的初始趋势；新增 Theta | 已知输出对照单测；`ImplVersion`/模型版本变更，旧晋升自动失效（预期行为，需在发布说明写明） |
| A5 直接多步 | GBDT 与岭回归增加“直接多步”选项（每个步长一个模型或带步长特征），默认保持递归以兼容 | 对比单测：同数据下长视野误差不高于递归版；回测无泄漏 |
| A6 KNN 修正 | 加互斥区（选中窗口间隔不小于窗口长度）与可选时刻约束 | 单测：重复事件不再被计 K 次 |
| A7 MSTL | 日+周双季节分解预测 | 合成日+周信号的对照单测；耗时在预算内 |
| A8 全局模型（设计） | 先写设计：特征、归一化、按模块分组、冷启动、版本；不实现 | 设计评审通过后再拆实现包 |
| A9 小型时序基础模型离线评估 | 只做离线评估，看值不值得为它引入外部服务；纯 Go 进程内跑不了 | 评估报告 |
| A10 周期画像分位数 | 新算法 `seasonal_profile`：按「周几 + 几点」分桶，每桶取带时间衰减的 P90、P95 | 单测：高峰时刻预测成高峰、周末与工作日不同、一次异常的一天不带偏（而 seasonal_naive 会）、桶样本少时回退、时区、参数校验 |
| A11 峰值包络趋势 | 新算法 `peak_envelope`：滚动最大值作包络，Theil-Sen 稳健外推，可算预计多久触顶 | 单测：锯齿加缓慢上涨上预测下一批峰值而不是均值、重启与异常峰不拖偏、不低于当前包络、不为负、触顶时间 |
| A12 组合预测 | 新算法 `combination`：成员各自预测，取中位数或按近期误差倒数加权 | 单测：不比最差成员差、权重跟着近期误差、历史不够的成员被略去、无泄漏、成员校验 |
| A13 变点后重置 | 做成每个非基线算法的参数 `reset_on_change`（同 A3 的做法）：检测最后一次水平突变，只用之后的历史 | 单测：突变位置找得准、稳定的上升与噪声不误报、小跳变与刚发生的突变不算、突变后的预测落在新水平、无泄漏、永远给够算法所需的历史 |

每个包交付后：更新本文件状态、进度文档、相关技能；改变算法输出的包要说明对已存晋升的影响。
